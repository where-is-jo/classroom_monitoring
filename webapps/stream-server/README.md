# stream-server

CCTV 또는 Jetson 장치에서 영상을 수신하고, 추론 가능한 형태의 프레임으로 전달하는 서비스 디렉터리다.

> 현재 상태: 구현 전. 프로토콜과 프레임 전달 방식은 아직 확정되지 않았다.

## 서비스 목적

영상 소스와의 연결을 유지하고, 끊김·재연결을 관리하며,
추론 서비스가 사용할 수 있는 형태로 프레임을 공급한다.

## 책임

- 카메라·장치와의 스트림 연결 수립 및 유지
- 연결 끊김 감지와 재연결
- 프레임 추출과 샘플링(모든 프레임을 추론에 보내지 않는 정책 포함)
- 연결 상태 및 프레임 처리량 지표 노출

## 포함해야 할 기능

- 스트림 소스 등록·해제
- 연결 상태 관리(연결됨 / 재시도 중 / 실패)
- 프레임 추출과 전달 경로
- 샘플링 주기 설정화
- 소스별 식별자 부여

## 포함하지 않아야 할 기능

- 객체 탐지·모델 추론 → `inference` 책임
- 영상의 장기 보관 정책 결정과 저장 실행
- 탐지 결과에 대한 비즈니스 판단 → `backend` 책임
- 사용자 대상 API 제공

## 예상 기술

| 항목 | 상태 | 비고 |
| --- | --- | --- |
| 언어 | Python | |
| 수신 프로토콜 | 결정 필요 | RTSP / WebRTC / HTTP 푸시 후보 |
| 프레임 처리 | 결정 필요 | OpenCV, GStreamer 후보 |
| 추론 전달 방식 | 결정 필요 | 동기 HTTP / 공유 큐 후보 |

프로토콜은 실제 장비(CCTV, Jetson) 사양을 확인한 뒤 결정하고, 결과를 ADR로 남긴다.

## 다른 서비스와의 관계

- 영상 소스(CCTV / Jetson): 외부 시스템이다. 접속 정보는 환경변수로 주입한다.
- `inference`: 프레임 공급 대상이다. 전달 방식 확정 전까지 임의 구현하지 않는다.
- `backend`: 스트림 연결 상태를 조회할 수 있게 한다. 조회 경로는 **결정 필요**.
- `frontend`: 직접 호출하지 않는다.
- `monitoring`: 연결 상태·프레임 처리량 지표를 노출한다.

## 영상 데이터와 메타데이터의 분리

영상 바이트와 탐지 메타데이터는 저장 책임을 분리한다.
메타데이터는 MongoDB, 영상·스냅샷은 MinIO에 보관한다([ADR-0003](../../docs/architecture/decisions/ADR-0003-metadata-store-mongodb.md), [ADR-0004](../../docs/architecture/decisions/ADR-0004-object-storage-minio.md)).

**stream-server가 MinIO에 직접 쓸지, backend를 거칠지는 결정 필요 항목이다.**
저장 범위와 보존 기간도 아직 합의되지 않았다.
확정 전까지 영상을 저장하는 기능을 만들지 않는다.

## 향후 구현 시 필요한 환경변수

값의 취급과 명명 규칙은 [환경변수 규칙](../../docs/conventions/environment-convention.md)을 따른다.
카메라 접속 자격 증명은 어떤 형태로도 저장소에 두지 않는다.

| 이름 | 용도 | 비고 |
| --- | --- | --- |
| `STREAM_SOURCES` | 연결할 영상 소스 목록 | 자격 증명은 분리해 주입 |
| `STREAM_CREDENTIALS_*` | 소스 접속 자격 증명 | 값은 절대 커밋 금지 |
| `FRAME_SAMPLE_INTERVAL` | 프레임 샘플링 주기 | 부하 조절용 |
| `RECONNECT_MAX_RETRY` | 재연결 최대 시도 횟수 | |
| `INFERENCE_TARGET` | 프레임 전달 대상 | 전달 방식 확정 후 |

## 테스트 전략

- 연결 상태 전이(연결 → 끊김 → 재시도 → 복구)를 실제 장비 없이 단위 테스트한다.
- 프레임 샘플링 로직은 고정 입력으로 검증한다.
- 실제 카메라가 필요한 테스트는 별도로 분리하고, 기본 테스트에 포함하지 않는다.
