# frontend

스마트 오피스 모니터링의 사용자·관리자용 웹 대시보드 서비스 디렉터리다.

> 현재 상태: 구현 전. 이 문서는 구현이 시작될 때 지켜야 할 책임 범위를 정의한다.
> 실행 명령, 화면 목록, API 경로는 실제 구현이 생긴 뒤 이 문서에 추가한다.

## 서비스 목적

관제 담당자와 일반 사용자가 오피스 공간의 상태(재실 여부, 탐지 이벤트, 장비 상태)를
브라우저에서 확인할 수 있게 한다. 데이터는 backend API를 통해서만 조회한다.

## 책임

- 화면 구성과 사용자 흐름
- backend API 호출과 응답의 화면 표현
- 실시간 상태 갱신의 표시 방식
- 로딩·빈 상태·오류 상태의 사용자 안내
- 화면 접근 권한에 따른 UI 노출 제어(권한 판정 자체는 backend 책임)

## 포함해야 할 기능

- 대시보드 화면(현재 상태 요약)
- 탐지 이벤트 목록 및 상세 조회
- 실시간 상태 표시 영역
- API 호출을 담당하는 클라이언트 계층(화면 코드와 분리)
- 오류·재시도 UI

## 포함하지 않아야 할 기능

- inference 서비스 또는 stream-server 직접 호출
- 데이터베이스·객체 저장소 직접 접근
- 모델 추론, 임계값 판정 등 비즈니스 판단 로직
- 비밀키·토큰의 소스 코드 내 하드코딩

## 예상 기술

| 항목 | 상태 | 비고 |
| --- | --- | --- |
| 언어 | TypeScript (결정 필요 아님, 팀 기본) | 타입 명시 필수 |
| 프레임워크 | 결정 필요 | React 계열 후보 |
| 실시간 전달 방식 | 결정 필요 | WebSocket / SSE / 폴링 후보 |
| 상태 관리·스타일링 | 결정 필요 | 프레임워크 확정 후 결정 |

기술 선택이 확정되면 그 이유를 [ADR](../../docs/architecture/decisions/)로 남긴다.

## 다른 서비스와의 관계

- `backend`: 유일한 데이터 조회·변경 경로다.
- `inference`, `stream-server`: 직접 호출하지 않는다. 필요한 결과는 backend가 중계한다.
- `monitoring`: 프론트엔드는 지표를 직접 조회하지 않는다. 필요한 경우 backend를 통한다.

영상 스트림을 화면에 직접 재생해야 하는 경우, 그 경로를 예외로 둘지 여부는 **결정 필요** 항목이며
확정 전까지 임의로 구현하지 않는다.

## 향후 구현 시 필요한 환경변수

값의 취급과 명명 규칙은 [환경변수 규칙](../../docs/conventions/environment-convention.md)을 따른다.

| 이름 | 용도 | 비고 |
| --- | --- | --- |
| `API_BASE_URL` | backend API 기본 주소 | 환경별로 다름 |
| `REALTIME_ENDPOINT` | 실시간 채널 주소 | 전달 방식 확정 후 필요 여부 재검토 |

## 테스트 전략

- 타입 검사와 린트를 기본 게이트로 둔다.
- API 클라이언트 계층은 응답 파싱과 오류 분기를 단위 테스트한다.
- 화면은 로딩·빈 상태·오류 상태가 각각 렌더링되는지 검증한다.
- 백엔드 응답은 테스트에서 실제 서버 대신 목(mock)으로 대체한다.
