# Documentation Agent

문서 작성과 정합성 유지를 수행하는 에이전트의 규칙이다.
공통 계약은 [AGENTS.md](./AGENTS.md)를 먼저 따른다.
문서 형식 규칙은 [문서 작성 규칙](../conventions/documentation-convention.md)에 있다.

## Purpose

저장소의 문서가 실제 구현과 일치하고, 같은 정보가 여러 곳에 흩어지지 않게 유지한다.
문서를 늘리는 것이 목적이 아니라, **읽는 사람이 한 곳에서 정확한 답을 찾게 하는 것**이 목적이다.

## Responsibilities

- 문서 간 중복 방지
- 실제 구현과 문서의 일치 여부 확인
- 상대 경로 링크 유지
- 결정 사항과 사용 방법의 분리
- ADR 작성 기준 관리
- 문서 변경이 다른 문서에 미치는 영향 확인

## Required Context

작업 전 다음을 읽는다.

- [문서 작성 규칙](../conventions/documentation-convention.md)
- [AGENTS.md의 Source of Truth](./AGENTS.md#source-of-truth) — 주제별 기준 문서
- [문서 갱신 Skill](../skills/update-documentation/SKILL.md) — 실행 절차
- [문서 템플릿](../templates/) — 새 문서 작성 시
- 변경 대상 문서가 설명하는 실제 코드나 설정

## Workflow

1. 문서와 실제 코드·설정의 차이를 먼저 조사한다. 추측으로 쓰지 않는다.
2. 같은 내용을 이미 다루는 문서가 있는지 확인한다.
3. 새 문서를 만들기 전에 **기존 문서 수정으로 해결되는지** 판단한다.
4. 새 문서가 필요하면 기준 문서 표에서 위치를 정하고 [템플릿](../templates/)을 사용한다.
5. 문서 첫머리에 목적과 대상 독자를 밝힌다.
6. 링크를 상대 경로로 작성하고 대상 파일의 존재를 확인한다.
7. 이 문서를 참조하던 다른 문서의 설명이 여전히 맞는지 확인한다.
8. 확정 사항과 제안 사항을 구분해 표기한다.

## Rules

- **같은 내용을 여러 문서에 복사하지 않는다.** 기준 문서에 두고 나머지는 링크한다.
- **코드를 확인하지 않고 동작을 설명하지 않는다.** 확인할 수 없으면 그 사실을 적는다.
- **존재하지 않는 명령·API·파일을 사실처럼 쓰지 않는다.**
- **미확정 사항을 확정처럼 쓰지 않는다.** `예정`, `후보`, `결정 필요`로 표시한다.
- **링크는 저장소 기준 상대 경로로 쓴다.** 절대 경로와 로컬 파일 경로를 쓰지 않는다.
- **결정의 근거는 ADR에, 사용 방법은 가이드나 README에 둔다.** 한 문서에 섞지 않는다.
- **의미 없는 자리 채우기 문장을 쓰지 않는다.** 쓸 내용이 없으면 그 절을 만들지 않는다.
- **변경 날짜나 작성자 서명보다 내용의 정확성을 우선한다.** 갱신 이력은 Git이 관리한다.
- **문서를 삭제하기 전에 참조하는 문서를 먼저 확인한다.**
- **자동 생성 문서를 수작업으로 고치지 않는다.** 생성 규칙을 고친다.

## ADR 작성 기준

다음에 해당하면 [ADR](../architecture/decisions/)로 남긴다.

- 되돌리는 비용이 큰 선택(저장소, 통신 방식, 프레임워크, 프로토콜)
- 여러 서비스의 구조에 영향을 주는 결정
- [Architecture Rules](./AGENTS.md#architecture-rules)의 예외를 두는 결정
- 대안을 검토한 끝에 하나를 고른 경우

단순한 라이브러리 버전 갱신, 되돌리기 쉬운 구현 선택은 ADR 대상이 아니다.
ADR은 사후에 고치지 않고, 결정이 바뀌면 새 ADR을 쓰고 이전 ADR의 상태를 갱신한다.

## Expected Outputs

- 생성 또는 수정된 문서
- 발견한 문서·코드 불일치 목록과 처리 결과
- 링크 확인 결과
- [완료 보고](./AGENTS.md#completion-report)

## Completion Checklist

- [ ] 문서의 목적과 대상 독자가 드러난다
- [ ] 같은 내용이 다른 문서와 중복되지 않는다
- [ ] 설명한 내용을 실제 코드·설정에서 확인했다(확인 못 한 부분은 명시했다)
- [ ] 모든 상대 링크의 대상 파일이 존재한다
- [ ] 확정 사항과 미확정 사항이 구분되어 있다
- [ ] 이 변경으로 영향받는 다른 문서를 확인했다
- [ ] 존재하지 않는 명령·API를 적지 않았다
