# AI Agent

추론 서비스와 영상 프레임 처리 작업을 수행하는 에이전트의 규칙이다.
공통 계약은 [AGENTS.md](./AGENTS.md)를 먼저 따른다.

대상 서비스는 [`deeplearning`](../../deeplearning/README.md)와
[`worker`](../../worker/README.md)다.

## Purpose

영상 프레임을 처리해 **사람을 탐지하고, 얼굴을 찾고, 학생을 식별**한다.
탐지 결과의 의미 해석과 저장은 담당하지 않는다.

목표 파이프라인은 사람 탐지 → 얼굴 탐지 → 얼굴 인식 → 갤러리 대조이며,
출력은 `student_id`와 bbox와 신뢰도까지다.

## 두 디렉터리의 경계

[결정 0009](../architecture/decisions.md#0009--추론-책임을-모델과-실행으로-나눈다)가 정한 경계다.

| 디렉터리 | 책임 |
| --- | --- |
| `deeplearning` | 모델 로딩·전처리·추론·후처리와 탐지 결과 스키마. **모델을 아는 유일한 곳** |
| `worker/inference` | 프레임 버퍼에서 프레임을 꺼내 호출하고 실패를 처리하는 **실행 단계** |

**현재 코드는 이 경계를 아직 만족하지 않는다.** `worker/inference`가 ultralytics를
직접 부르고 `deeplearning`에는 코드가 없다. 새 모델 코드는 `deeplearning`에 만들고,
기존 호출은 `deeplearning` 구현 시 이관한다.

## Responsibilities

- 영상 프레임 수신과 전처리
- 모델 로딩과 추론 실행
- 얼굴 등록 샘플의 embedding 생성과 갤러리 대조
- 모델 입출력 스키마 정의와 유지
- CPU/GPU 실행 환경 분기
- threshold 등 추론 파라미터의 설정화
- 추론 지연·처리량·식별 성공률 등 성능 지표 노출
- 모델 파일과 애플리케이션 코드의 분리 유지

## Workflow

1. 입력(프레임 형식, 해상도, 색공간)과 출력(탐지 결과 스키마)을 먼저 확정한다.
2. 출력 스키마를 바꾸는 작업이면 fastapi 영향을 먼저 확인하고 보고한다.
3. 전처리·후처리를 모델 호출과 분리해 구현한다.
4. 모델 경로·버전·장치·임계값을 설정으로 주입받게 한다.
5. 모델 없이 검증 가능한 부분(전처리, 결과 변환)을 단위 테스트한다.
6. 성능 관련 변경이면 측정 방법과 조건을 정하고 실제로 측정한다.
7. 스키마·파라미터·모델 버전이 바뀌었으면 서비스 README를 갱신한다.

## Rules

- **모델 가중치 파일을 저장소에 커밋하지 않는다.** 경로와 버전은 환경변수로 주입한다.
- **모델 경로·임계값을 코드에 하드코딩하지 않는다.**
- **모델은 요청마다 로딩하지 않는다.** 프로세스 시작 시 1회 로딩을 원칙으로 한다.
- **탐지 결과를 비즈니스 의미로 해석하지 않는다.** `student_001, 신뢰도 0.87, bbox`까지가
  이 서비스의 출력이고, `PRESENT`나 `WRONG_SEAT`으로의 해석은 fastapi 책임이다.
  **탐지 결과 스키마와 추론 코드에 업무 상태 어휘를 넣지 않는다.**
- **식별하지 못한 것을 억지로 식별하지 않는다.** 신뢰도가 기준 미만이면 `UNKNOWN`으로
  두고 가장 가까운 학생을 고르지 않는다. 오인식은 다른 학생의 정보를 노출하는 사고다.
- **탐지 결과를 이 서비스에서 영속 저장하지 않는다.**
- **측정하지 않은 성능 수치를 문서나 보고에 적지 않는다.** FPS, 지연 시간, 정확도,
  식별 성공률이 모두 해당한다.
- **임계값을 조정해 결과를 맞추는 방식으로 문제를 덮지 않는다.** 조정했으면 근거와 함께 보고한다.
- **작은 얼굴 문제를 Super Resolution으로 먼저 풀지 않는다.** 카메라 위치 개선 →
  해상도·렌즈·화각 조정 → 작은 얼굴 탐지기 검증 → crop 파이프라인 개선 순으로
  시도하고, 그래도 부족할 때 검토한다.
- **GPU 전용 코드를 기본 경로로 만들지 않는다.** CPU 실행 경로를 함께 유지한다.
- **`worker`에 모델 종류·가중치·전처리를, `deeplearning`에 스트림 연결 관리와 프레임
  수명 관리를 넣지 않는다.**
- **얼굴 이미지와 embedding이 로그·테스트 자산·저장소에 남지 않게 한다.**
  테스트에는 실제 사람의 얼굴을 쓰지 않는다.
- 모델 종류·버전, 탐지 결과 전달 방식, `deeplearning` 호출 방식, 실행 장치는
  **결정 필요** 항목이다. 확정 전이면 특정 선택에 강하게 결합된 구조를 굳히지 않고,
  확정 시 [결정 기록](../architecture/decisions.md)에 남긴다.

- [ ] 모델 경로·버전·장치·임계값이 설정으로 주입된다
- [ ] 모델 로딩이 요청 경로에 있지 않다
- [ ] 비즈니스 해석 로직과 업무 상태 어휘가 포함되지 않았다

- [ ] 모델 없이 실행 가능한 테스트를 실제로 실행했다
- [ ] 문서에 적은 성능 수치는 실제 측정값이다(측정하지 않았으면 적지 않았다)
