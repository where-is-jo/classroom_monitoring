# FastAPI Agent

FastAPI 웹 애플리케이션 작업을 수행하는 에이전트의 규칙이다.
API와 Jinja2 화면을 모두 다룬다.
공통 계약은 [AGENTS.md](./AGENTS.md)를 먼저 따른다.

## Purpose

외부 요청의 유일한 진입점인 웹 애플리케이션을 만들고 유지한다.
요청을 검증하고, 비즈니스 로직을 수행하고, 내부 서비스와 저장소를 조정해
API 응답 또는 Jinja2로 렌더링한 화면을 돌려준다.

**이 서비스가 학생 상태 판정을 소유한다.** 탐지 결과를 `PRESENT` / `WRONG_SEAT` /
`ABSENT`로 바꾸는 규칙은 여기 있고, 다른 서비스에 두지 않는다
([결정 0008](../architecture/decisions.md#0008--학생-상태-판정을-rule-engine으로-분리하고-fastapi가-소유한다)).

## Responsibilities

- API 엔드포인트 정의와 요청·응답 스키마 관리
- Jinja2 템플릿 작성과 화면 구성
- 비즈니스 로직 구현(프레임워크에 의존하지 않는 계층)
- **학생 상태 판정 규칙** — 좌석 대조, 수업 시간 정책, 유예 시간, 상태 이력
- deeplearning·worker 등 내부 서비스 연동
- 데이터 저장소 접근
- 오류 처리와 오류 응답·오류 화면 통일
- 접근성과 상태별 화면 처리
- 테스트 작성과 API 문서 유지

## Workflow

1. 기존 라우터·서비스·스키마와 **포트·어댑터** 구조를 조사한다. 유사한 엔드포인트가 있으면 그 패턴을 따른다.
2. API 계약(경로, 메서드, 요청·응답 필드, 상태 코드, 오류 케이스)을 먼저 정의한다.
3. 계약이 기존 소비자에 영향을 주는지 확인한다. 영향이 있으면 구현 전에 보고한다.
4. Pydantic 스키마를 정의한다.
5. 비즈니스 로직을 서비스 계층에 구현한다. 외부 I/O가 필요하면 포트로 선언한 뒤 어댑터를 구현하고, 라우터는 HTTP 관심사만 다루게 한다.
6. 오류 케이스를 명시적으로 처리한다.
7. 단위 테스트와 API 테스트를 작성하고 실행한다.
8. API 문서와 서비스 README를 갱신한다.

## Rules

- **라우터 함수에 비즈니스 로직을 두지 않는다.** 라우터는 입력 변환, 서비스 호출, 응답 변환까지만 한다.
- **서비스 계층은 FastAPI에 의존하지 않는다.** `Request`, `HTTPException`을 서비스 계층에서 쓰지 않는다.
- **외부 I/O는 포트를 통한다.** 서비스 계층이 어댑터 구현체(MongoDB, MinIO, HTTP 클라이언트)를 직접 import하지 않는다.
- **포트를 남발하지 않는다.** 프로세스 밖과 통신하는 지점에만 만든다. 같은 프로세스 안의 서비스 호출과 순수 계산 로직에는 만들지 않는다. 판단 기준은 [결정 0001](../architecture/decisions.md#0001--fastapi-계층형-구조와-경계-포트)에 있다.
- **설계 패턴은 [결정 0002](../architecture/decisions.md#0002--설계-패턴-적용-범위와-판단-기준)의 표에 있는 것만 만든다.** 표의 판정 질문에 전부 예라고 답할 수 없으면 만들지 않는다. 지시가 없을 때의 기본 동작은 "만들지 않는다"다. 표에 없는 패턴을 쓰려면 결정 기록에 항목을 먼저 남긴다.
- **한 기능 안에 별도 파사드를 두지 않는다.** `service.py`가 이미 라우터에 대한 파사드다. `facade.py` 같은 파일을 만들지 않는다.
- **변형이 하나뿐인 추상화를 만들지 않는다.** 구현체가 하나인 인터페이스, 분기를 대체할 뿐인 클래스 계층이 해당한다. 판단 로직은 변형이 실제로 둘 이상 생길 때까지 순수 함수로 둔다.
- **모든 요청·응답을 Pydantic 스키마로 정의한다.** 원시 dict를 그대로 반환하지 않는다.
- **기존 API 계약을 임의로 바꾸지 않는다.** 필드 삭제·이름 변경·타입 변경·필수화는 승인이 필요하다.
- **오류를 삼키지 않는다.** `except: pass` 형태를 쓰지 않고, 예외를 적절한 상태 코드로 변환한다.
- **오류 응답에 내부 정보를 노출하지 않는다.** 스택 트레이스, 쿼리, 내부 주소는 로그로만 남긴다.
- **로그에 비밀값과 개인정보를 남기지 않는다.** 토큰, 비밀번호, 원본 영상 경로,
  얼굴 embedding, 학생 실명이 해당한다.
- **설정값을 하드코딩하지 않는다.** 주소, 임계값, 타임아웃은 환경변수 또는 설정으로 뺀다.
  **유예 시간과 신뢰도 임계값도 여기 포함된다.**
- **내부 서비스 호출에 타임아웃을 지정한다.** 무한 대기를 만들지 않는다.
- **추론 연산과 스트림 처리를 fastapi에 구현하지 않는다.** 해당 서비스에 위임한다.
- **파괴적 DB 작업을 요청 없이 수행하지 않는다.**

### 학생 상태 판정

- **조회 GET이 저장된 상태를 바꾸지 않는다.** 시간 정책은 명시적인 평가 요청이나
  탐지 이벤트 수신에서만 적용한다.
- **미관측을 부재로 바꾸지 않는다.** 카메라 장애, 가림, 조회 실패를 `ABSENT`로
  표시하지 않는다. 유예 시간을 넘긴 미식별만 `ABSENT`다.
- **신뢰도 미달 식별에 이름을 붙이지 않는다.** `UNKNOWN`으로 둔다. 오인식은 다른
  학생의 정보를 노출하는 사고다.
- **탐지 이벤트를 `event_id`로 멱등 처리한다.** 같은 이벤트가 두 번 들어와도 상태와
  이력이 한 번만 바뀐다. 오래된 관측이 현재 상태를 되돌리지 않는다.
- **상태 전이의 근거 이벤트를 이력에 남긴다.** 출결은 사람에게 불이익을 줄 수 있는
  판정이라 되짚을 수 있어야 한다.
- **판정 규칙을 상태별 클래스로 나누지 않는다.** 순수 함수로 시작한다
  ([결정 0002](../architecture/decisions.md#0002--설계-패턴-적용-범위와-판단-기준)).

### 얼굴 데이터

- **얼굴 embedding과 원본 이미지를 API 응답에 넣지 않는다.** 등록 여부, 샘플 수,
  품질 판정 결과, 모델 버전, 등록 시각까지만 돌려준다.
- **얼굴 이미지를 화면 목록으로 보여 주지 않는다.** 등록 중 방금 찍은 샘플 확인만 예외다.
- **얼굴 프로필을 학생 단위로 삭제할 수 있게 만든다.** embedding과 원본을 함께 지운다.
- **동의·보존·접근 권한이 합의되기 전에 얼굴 데이터를 다루는 기능을 만들지 않는다.**

### 화면 작업

- **템플릿에 비즈니스 판단을 두지 않는다.** 임계값 해석, 상태 분류는 서비스 계층에서 끝낸다.
- **정상·빈 상태·오류 상태를 모두 만든다.** "데이터 없음"과 "조회 실패"를 구분해 표시한다.
- **상태를 색으로만 구분하지 않는다.** 문구나 아이콘을 함께 쓴다.
- 이미지·아이콘에 대체 텍스트를 넣고, 키보드로 모든 조작이 가능하게 한다.
- 좁은 화면에서 레이아웃이 깨지지 않는지 확인한다.
- **브라우저 스크립트를 비즈니스 로직 저장소로 쓰지 않는다.** 화면 보조에 한정한다.
- 템플릿에서 저장소나 외부 서비스를 직접 호출하지 않는다.
- 저장소는 MongoDB, 객체 저장소는 MinIO로 확정됐다([결정 0003](../architecture/decisions.md#0003--메타데이터-저장소로-mongodb-채택), [결정 0004](../architecture/decisions.md#0004--영상과-얼굴-이미지-저장소로-minio-채택)). 관련 코드는 어댑터에만 둔다.
- 탐지 결과는 HTTP로 받고 화면은 SSE로 갱신하며, 영상은 WebRTC로 재생한다
  ([결정 0027](../architecture/decisions.md#0027--실시간-관제-전달을-httpwebrtcsse로-구성한다)).
  알림 채널은 아직 **결정 필요**다.
- **영상 저장 범위를 넓히는 기능을 먼저 만들지 않는다.** 보존 기간과 접근 권한이 합의되지 않았다. 결정 0004의 남은 일을 확인한다.
- **MVP의 제품 사용자는 관리자 하나다.** 역할별 화면·권한 분기를 미리 만들지 않는다
  ([결정 0010](../architecture/decisions.md#0010--mvp-제품-사용자를-관리자-하나로-한정한다)).

## Completion Checklist

- [ ] API 계약을 먼저 정의하고 기존 소비자 영향을 확인했다
- [ ] 라우터와 비즈니스 로직이 분리되어 있다
- [ ] 서비스 계층이 어댑터 구현체를 직접 참조하지 않는다
- [ ] 새로 만든 포트가 있다면 프로세스 외부 I/O 경계에 해당한다
- [ ] 새로 도입한 설계 패턴이 있다면 결정 0002의 판정 질문을 전부 만족한다
- [ ] 구현체나 변형이 하나뿐인 추상화를 만들지 않았다
- [ ] 화면을 추가·수정했다면 빈 상태와 오류 상태를 함께 처리했다
- [ ] 템플릿에 비즈니스 판단이 들어가지 않았다
- [ ] 키보드 조작과 대체 텍스트를 확인했다
- [ ] 상태 판정을 건드렸다면 조회 GET이 상태를 바꾸지 않는다
- [ ] 미관측과 조회 실패가 `ABSENT`로 표시되지 않는다
- [ ] 탐지 이벤트가 멱등 처리되고 오래된 관측이 현재 상태를 되돌리지 않는다
- [ ] 얼굴 embedding·원본 이미지가 응답·로그·화면 목록에 없다
- [ ] 요청·응답이 Pydantic 스키마로 정의되어 있다
- [ ] 오류 케이스가 명시적으로 처리되고 상태 코드가 규칙에 맞다
- [ ] 오류 응답에 내부 정보가 노출되지 않는다
- [ ] 로그에 비밀값·개인정보가 없다
- [ ] 하드코딩된 설정값이 없다
- [ ] 외부 호출에 타임아웃이 있다
- [ ] 테스트를 실제로 실행했다
- [ ] 린트(ruff)와 타입 검사(mypy strict)가 통과한다
- [ ] API 문서와 README를 갱신했다
