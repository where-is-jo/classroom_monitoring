# 버그 조사 프롬프트

장애나 오동작을 조사할 때 사용한다.
재현 → 원인 분석 → 최소 수정 → 회귀 테스트 순서를 강제한다.

## 사용법

1. 아래 변수 값을 정한다. 증상과 재현 방법은 최대한 구체적으로 적는다.
2. `## 프롬프트` 블록을 복사해 변수를 치환한 뒤 에이전트에게 전달한다.

관련 문서: [AGENTS.md](../agents/AGENTS.md) · [코드 리뷰 Skill](../skills/review-code/SKILL.md)

## 변수

| 변수 | 설명 | 예 |
| --- | --- | --- |
| `{{SYMPTOM}}` | 관측된 증상 | `이벤트 목록이 비어서 표시됨` |
| `{{REPRODUCTION}}` | 재현 방법(모르면 `미확인`) | |
| `{{EXPECTED}}` | 기대한 동작 | |
| `{{ACTUAL}}` | 실제 동작 | |
| `{{ENVIRONMENT}}` | 발생 환경 | `개발 환경` |
| `{{FREQUENCY}}` | 발생 빈도 | `간헐적, 하루 2~3회` |
| `{{RECENT_CHANGES}}` | 관련 있어 보이는 최근 변경 | |
| `{{LOGS}}` | 확보한 로그·오류 메시지 | |

## 프롬프트

```text
아래 문제를 조사한다.

## 작업 목적
증상의 원인을 찾아 최소 범위로 수정하고, 같은 문제가 다시 생기면
잡히도록 테스트를 남긴다. 증상을 가리는 수정은 목적이 아니다.

## 입력 정보
- 증상: {{SYMPTOM}}
- 재현 방법: {{REPRODUCTION}}
- 기대 동작: {{EXPECTED}}
- 실제 동작: {{ACTUAL}}
- 환경: {{ENVIRONMENT}}
- 빈도: {{FREQUENCY}}
- 최근 변경: {{RECENT_CHANGES}}
- 로그: {{LOGS}}

## 참고할 Agent
- `docs/agents/AGENTS.md` (공통 계약, 반드시 먼저 읽는다)
- 문제가 발생한 영역의 Agent 문서(frontend / backend / ai / rpa)

## 참고할 Skill
- `docs/skills/review-code/SKILL.md` — 원인 후보를 좁힐 때 점검 순서로 사용
- 수정이 문서에 영향을 주면: `docs/skills/update-documentation/SKILL.md`

## 작업 절차
1. **재현**
   - 먼저 문제를 재현한다. 재현되지 않으면 수정하지 말고,
     재현에 필요한 정보를 요청한다.
   - 재현 조건(입력, 타이밍, 데이터 상태)을 기록한다.
2. **범위 좁히기**
   - 증상이 나타나는 최소 경로를 찾는다.
   - 로그와 실제 값으로 확인한다. 코드를 읽은 인상만으로 단정하지 않는다.
3. **원인 확정**
   - 왜 그 코드가 이 입력에서 잘못 동작하는지 설명할 수 있어야 한다.
   - 설명하지 못하면 아직 원인이 아니다. 계속 조사한다.
4. **최소 수정**
   - 원인 지점만 고친다. 주변 코드를 함께 정리하지 않는다.
   - 같은 원인이 다른 곳에도 있으면 수정하지 말고 목록으로 보고한다.
5. **회귀 테스트**
   - 수정 전에는 실패하고 수정 후에는 통과하는 테스트를 추가한다.
   - 테스트가 실제로 문제를 잡는지 확인한다(수정을 되돌려 실패를 확인).
6. **영향 확인**
   - 수정이 다른 동작을 바꾸지 않는지 기존 테스트로 확인한다.

## 금지 사항
- 재현하지 못한 상태에서 추측으로 수정하지 않는다.
- 예외를 잡아 무시하는 방식으로 증상을 덮지 않는다.
- 원인을 모른 채 재시도·대기 시간 추가로 넘기지 않는다.
- 실패하는 테스트를 삭제하거나 조건을 약화시키지 않는다.
- 버그 수정과 함께 리팩터링·기능 추가를 섞지 않는다.
- 임계값이나 설정값을 조정해 증상만 사라지게 하지 않는다.
  (조정이 실제 원인이면 근거와 함께 보고한다.)
- 운영 데이터를 임의로 수정해 상태를 맞추지 않는다.
- 원인을 확정하지 못했으면 확정한 것처럼 보고하지 않는다.

## 검증 방법
- 원래 재현 절차로 증상이 사라졌는지 확인한다.
- 추가한 회귀 테스트가 수정 전에는 실패했는지 확인한다.
- 기존 테스트가 모두 통과하는지 확인한다.
- 간헐적 문제라면 어떤 조건에서 확인했는지, 확인 범위의 한계를 밝힌다.

## 완료 보고 형식
## 작업 요약
## 재현 조건
## 원인
## 생성 또는 변경한 파일
## 실행한 검증
## 실행하지 못한 검증
## 같은 원인이 있을 수 있는 다른 위치
## 남은 위험 또는 후속 작업
```
