# Review Code

## Purpose

변경된 코드를 검토할 때, 취향 문제로 시간을 쓰지 않고
실제로 문제가 될 항목을 중요도 순으로 짚기 위한 절차다.

## When to Use

- Pull Request 리뷰
- 병합 전 자체 점검
- 외부에서 받은 코드 검토

## Required Inputs

| 입력 | 설명 |
| --- | --- |
| 변경 범위 | 대상 브랜치 또는 변경 파일 목록 |
| 변경 의도 | 이 변경이 해결하려는 문제 |
| 관련 요구사항 | 이슈, 명세, 프롬프트 |
| 실행된 검증 | 작성자가 돌린 테스트와 결과 |

## Preconditions

- 변경 의도를 파악했다
- 대상 영역의 [Agent 문서](../../agents/AGENTS.md#역할별-agent-문서)와 [개발 규칙](../../conventions/)을 확인했다
- 변경 전 코드가 어떻게 동작했는지 확인했다

## Procedure

아래 순서로 본다. 위쪽 항목이 더 중요하다.

1. **요구사항 충족 여부**
   - 의도한 문제를 실제로 해결하는가.
   - 요청하지 않은 변경이 섞여 있지 않은가.

2. **오류 가능성**
   - 경계값(0, 빈 목록, null, 최대값) 처리
   - 예외를 삼키는 코드(`except: pass`, 빈 catch)
   - 실패 경로에서 자원이 정리되는가
   - 외부 호출에 타임아웃이 있는가

3. **보안 문제**
   - 비밀값·토큰이 코드나 로그에 노출되는가
   - 입력 검증이 있는가
   - 권한 확인이 우회 가능한가
   - 오류 응답이 내부 정보를 노출하는가

4. **데이터 손실 가능성**
   - 되돌릴 수 없는 삭제·덮어쓰기
   - 마이그레이션의 롤백 가능성
   - 부분 실패 시 데이터가 어중간한 상태로 남는가

5. **동시성 문제**
   - 공유 상태 접근
   - 중복 실행 시 결과가 어긋나는가
   - 순서 의존성

6. **성능 문제**
   - 반복문 안의 네트워크·DB 호출
   - 불필요하게 큰 데이터 적재
   - 요청 경로에서의 무거운 초기화(예: 모델 로딩)
   - 추측하지 말고, 문제로 보이면 근거(호출 횟수, 데이터 규모)를 적는다

7. **테스트 누락**
   - 변경된 동작에 대응하는 테스트가 있는가
   - 실패 케이스가 검증되는가
   - 테스트를 통과시키려고 테스트를 약화시키지 않았는가

8. **문서 불일치**
   - README·API 문서가 변경을 반영하는가
   - 문서에 없던 새 환경변수가 생겼는가

## Validation

- 지적한 문제를 **재현 조건과 함께** 적는다. "문제가 될 수 있다"만으로는 부족하다.
- 확신이 없으면 단정하지 말고 질문 형태로 적는다.
- 가능하면 변경분을 실제로 실행하거나 테스트를 돌려 확인한다.
- 실행하지 않았으면 리뷰에 그렇게 밝힌다.

## Expected Output

중요도 순으로 정리한 리뷰 결과.

```markdown
## 병합 전 수정 필요
- [파일:줄] 문제 — 어떤 입력·상황에서 무엇이 잘못되는가

## 수정 권장
- [파일:줄] 문제와 이유

## 참고 의견
- 반영하지 않아도 병합 가능한 제안

## 확인한 것 / 확인하지 못한 것
```

## Failure Handling

| 상황 | 대응 |
| --- | --- |
| 변경 의도를 모르겠다 | 추측해서 지적하지 말고 의도를 먼저 묻는다 |
| 변경 범위가 지나치게 크다 | 리뷰 가능한 단위로 나눠줄 것을 요청한다 |
| 문제인지 확신이 없다 | 단정하지 말고 질문으로 남긴다 |
| 취향 차이다 | 규칙 문서에 근거가 없으면 `참고 의견`에 둔다 |
| 기존 코드의 문제를 발견했다 | 이번 변경과 분리해 별도 항목으로 보고한다 |
| 지적이 너무 많다 | 병합을 막는 항목을 먼저 추리고 나머지는 뒤로 뺀다 |

## Completion Checklist

- [ ] 요구사항 충족 여부를 확인했다
- [ ] 오류·보안·데이터 손실·동시성·성능을 순서대로 점검했다
- [ ] 테스트 누락과 문서 불일치를 확인했다
- [ ] 각 지적에 재현 조건 또는 근거를 적었다
- [ ] 중요도 순으로 정리했다
- [ ] 취향 문제와 실제 문제를 구분했다
- [ ] 실행한 검증과 실행하지 않은 검증을 밝혔다
