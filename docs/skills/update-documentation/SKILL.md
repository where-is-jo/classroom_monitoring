# Update Documentation

## Purpose

문서를 실제 코드·설정과 맞추고, 같은 정보가 여러 문서에 흩어지지 않게
정리하기 위한 절차다. 문서를 늘리는 것이 목적이 아니다.

## When to Use

- 코드 변경으로 문서가 사실과 달라졌을 때
- 문서를 읽고 따라 했는데 동작하지 않는다는 보고가 있을 때
- 결정이 확정되어 미확정 표기를 갱신해야 할 때
- 새 서비스·RPA가 추가되었을 때

다음에는 사용하지 않는다.

- 새 기능 구현과 함께 하는 문서 갱신(해당 기능의 Skill에 포함된다)

## Required Inputs

| 입력 | 설명 |
| --- | --- |
| 갱신 범위 | 대상 문서 또는 대상 영역 |
| 변경 근거 | 어떤 코드·설정 변경 때문인가 |
| 확인 가능한 출처 | 실제 코드, 설정 파일, 실행 결과 |

## Preconditions

- [문서 작성 규칙](../../conventions/documentation-convention.md)과 [documentation-agent](../../agents/documentation-agent.md)를 읽었다
- [Source of Truth](../../agents/AGENTS.md#source-of-truth)에서 해당 주제의 기준 문서를 확인했다

## Procedure

1. **불일치 조사**
   - 문서의 서술을 하나씩 실제 코드·설정과 대조한다.
   - 확인 못 한 항목을 따로 표시한다. 추측으로 메우지 않는다.
   - 실행 명령은 실제로 실행해 확인한다. 확인 못 하면 문서에서 뺀다.

2. **중복 확인**
   - 같은 내용을 다루는 다른 문서가 있는지 찾는다.
   - 중복이 있으면 기준 문서 하나만 남기고 나머지는 링크로 바꾼다.

3. **기존 문서 수정 우선**
   - 새 문서를 만들기 전에 기존 문서 수정으로 해결되는지 판단한다.
   - 새 문서가 꼭 필요하면 위치를 기준 문서 표에 맞추고 [템플릿](../../templates/)을 사용한다.

4. **내용 정리**
   - 사실(현재 그렇다), 결정(그렇게 하기로 했다), 예정(아직 아니다)을 구분해 표기한다.
   - 미확정 항목은 `예정`, `후보`, `결정 필요`로 표시한다.
   - 문서 첫머리에 목적과 대상 독자를 밝힌다.

5. **링크 정리**
   - 상대 경로로 작성한다.
   - 대상 파일이 실제로 존재하는지 확인한다.
   - 파일을 옮기거나 지웠으면 참조하던 문서를 모두 고친다.

6. **영향 확인**
   - 이 문서를 참조하던 다른 문서의 설명이 여전히 맞는지 확인한다.
   - 루트 README의 현재 단계·미결정 항목 목록도 갱신 대상인지 본다.

## Validation

- 모든 상대 링크의 대상 파일 존재를 확인한다.
- 문서에 남긴 명령을 실제로 실행해 본다(실행 가능한 경우).
- 갱신한 내용의 근거가 된 코드 위치를 보고에 적는다.
- 중복이 제거되었는지 확인한다.

변경 날짜나 작성자 서명을 추가하지 않는다. 이력은 Git이 관리한다.

## Expected Output

- 수정된 문서
- 발견한 불일치 목록과 처리 결과(수정함 / 코드 쪽 문제로 보고함 / 확인 불가)
- 링크 확인 결과
- [완료 보고](../../agents/AGENTS.md#completion-report)

## Failure Handling

| 상황 | 대응 |
| --- | --- |
| 코드와 문서 중 어느 쪽이 맞는지 모르겠다 | 코드를 사실로 보되, 문서 쪽 의도가 맞아 보이면 고치지 말고 보고한다 |
| 코드가 잘못된 것으로 보인다 | 문서만 코드에 맞추지 말고 불일치를 보고한다 |
| 확인할 수 없는 서술이 있다 | 사실처럼 남기지 말고 확인 불가 항목으로 보고한다 |
| 같은 내용의 문서가 여러 개다 | 임의로 삭제하지 말고 통합안을 제시한 뒤 진행한다 |
| 문서가 지나치게 길다 | 무조건 줄이지 말고, 중복과 일반론부터 제거한다 |
| 미확정 사항을 적어야 한다 | 확정처럼 쓰지 말고 `결정 필요`로 표시한다 |

## Completion Checklist

- [ ] 서술을 실제 코드·설정과 대조했다
- [ ] 확인하지 못한 항목을 보고에 밝혔다
- [ ] 중복 내용을 기준 문서로 모았다
- [ ] 새 문서 대신 기존 문서 수정으로 해결 가능한지 검토했다
- [ ] 사실·결정·예정을 구분해 표기했다
- [ ] 모든 상대 링크의 대상이 존재한다
- [ ] 이 변경으로 영향받는 다른 문서를 확인했다
- [ ] 검증하지 않은 실행 명령을 남기지 않았다
