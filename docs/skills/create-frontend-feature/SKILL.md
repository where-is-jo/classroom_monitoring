# Create Frontend Feature

## Purpose

대시보드에 화면이나 기능을 추가할 때, API 호출 계층을 분리하고
모든 상태(로딩·빈 상태·오류)를 빠뜨리지 않고 구현하기 위한 절차다.

## When to Use

- 새 화면이나 화면 내 기능 영역을 추가할 때
- 기존 화면에 새 데이터 표시를 추가할 때
- 실시간 상태 표시를 붙일 때

다음에는 사용하지 않는다.

- 문구·색상만 바꾸는 수정
- 백엔드 응답 변경 없이 스타일만 고치는 작업

## Required Inputs

| 입력 | 설명 |
| --- | --- |
| 화면 목적 | 사용자가 이 화면에서 무엇을 판단하는가 |
| 사용자 흐름 | 진입 경로, 조작, 이탈 경로 |
| 필요한 데이터 | 표시할 항목과 출처 API |
| 갱신 방식 | 1회 조회인가, 주기적 갱신인가, 실시간인가 |
| 권한 | 누가 이 화면을 보는가 |

## Preconditions

- [`webapps/frontend/README.md`](../../../webapps/frontend/README.md)와 [frontend-agent](../../agents/frontend-agent.md)를 읽었다
- 필요한 데이터를 제공하는 backend API가 **이미 존재하는지** 확인했다
- 기존 컴포넌트와 API 클라이언트를 조사했다

## Procedure

1. **요구 화면과 흐름 확인**
   - 화면에 표시할 항목과 사용자가 취할 동작을 목록으로 적는다.
   - 애매한 항목은 구현 전에 질문한다.

2. **API 확인**
   - 필요한 데이터를 backend가 제공하는지 확인한다.
   - 없으면 프론트에서 우회하지 말고 백엔드 작업으로 분리해 보고한다.

3. **재사용 확인**
   - 유사한 컴포넌트, 테이블, 상태 표시, API 클라이언트가 있는지 찾는다.
   - 비슷한 것을 새로 만들지 말고 기존 것을 확장할 수 있는지 먼저 본다.

4. **API 호출 계층 작성**
   - 호출 함수와 응답 타입을 화면 코드와 분리해 정의한다.
   - 컴포넌트가 직접 HTTP 호출을 하지 않게 한다.

5. **상태별 UI 구현**
   - 정상, 로딩, 빈 상태, 오류 네 가지를 모두 만든다.
   - "데이터 없음"과 "조회 실패"를 다르게 표시한다.
   - 오류에는 가능한 경우 재시도 수단을 준다.

6. **갱신 방식 구현**
   - 주기적 갱신이면 주기를 설정값으로 두고 근거를 남긴다.
   - 실시간 방식은 **결정 필요** 항목이므로 특정 방식에 강결합되지 않게 감싼다.

7. **반응형과 접근성 확인**
   - 좁은 화면에서 레이아웃이 깨지지 않는지 확인한다.
   - 키보드로 모든 조작이 가능한지, 이미지·아이콘에 대체 텍스트가 있는지 확인한다.
   - 상태를 색으로만 구분하지 않는다(문구나 아이콘 병행).

8. **타입 검사와 테스트**

## Validation

실제로 실행한다.

- 타입 검사와 린트
- API 클라이언트 단위 테스트(응답 파싱, 오류 분기)
- 컴포넌트 테스트(로딩·빈 상태·오류 렌더링)
- 좁은 화면 폭에서의 표시 확인
- 키보드 조작 확인

실행 명령은 프론트엔드 구현이 생긴 뒤 `webapps/frontend/README.md`에 기록한다.

## Expected Output

- 화면 컴포넌트와 라우팅
- API 클라이언트 함수와 응답 타입
- 상태별 UI
- 테스트
- 갱신된 서비스 README(화면·흐름이 바뀐 경우)
- [완료 보고](../../agents/AGENTS.md#completion-report)

## Failure Handling

| 상황 | 대응 |
| --- | --- |
| 필요한 API가 없다 | 프론트에서 우회 구현하지 말고 백엔드 작업으로 분리해 보고한다 |
| API 응답이 화면 요구와 다르다 | 화면에서 억지로 가공하기 전에 응답 자체가 적절한지 백엔드와 확인한다 |
| 응답 타입이 불명확하다 | `any`로 넘기지 말고 실제 응답을 확인해 타입을 정의한다 |
| 실시간 방식이 미확정이다 | 폴링 등 단순한 방식으로 감싸 구현하고, 교체 지점을 한 곳에 모아 보고한다 |
| 기존 컴포넌트와 요구가 조금 다르다 | 복사본을 만들기 전에 확장 가능한지 검토하고, 복사했다면 이유를 보고한다 |

## Completion Checklist

- [ ] backend API만 사용했다
- [ ] API 호출 계층이 화면 코드와 분리되어 있다
- [ ] 로딩·빈 상태·오류 상태를 모두 구현했다
- [ ] "데이터 없음"과 "조회 실패"를 구분했다
- [ ] 응답 타입이 명시되어 있다
- [ ] 좁은 화면에서 표시를 확인했다
- [ ] 키보드 조작과 대체 텍스트를 확인했다
- [ ] 색만으로 상태를 구분하지 않는다
- [ ] 타입 검사·린트·테스트를 실제로 실행했다
- [ ] 하드코딩된 주소·비밀값이 없다
