# 학생 모니터링 MVP 명세

**목적**: 강의실 카메라로 학생을 식별해 재석·잘못된 자리·부재를 자동 판정하는
MVP의 범위, 도메인 구조, 계약, 완료 조건을 정한다.
**대상 독자**: 이 기능을 구현·검토하는 팀원과 AI 에이전트.

> **상태 표기**: 이 문서에서 서술하는 목표 동작은 대부분 `예정`이다.
> 이미 구현된 사실은 [현재 구현 사실](#현재-구현-사실)에 따로 모았다.
> 합의가 필요한 항목은 `결정 필요`로 표시한다.
>
> 확정된 기술 결정의 근거는 [결정 기록](../architecture/decisions.md)에 있고,
> 서비스 관계와 미결정 항목의 정본은 [아키텍처](../architecture/README.md)다.
> 여기서 반복하지 않는다.

## 개요

관리자가 강의실을 돌며 학생을 일일이 확인하는 일을 시스템이 대신한다.

강의실 카메라 영상에서 학생을 식별하고, 그 학생의 현재 좌석을 지정 좌석과 비교하고,
수업 시간과 유예 시간을 함께 적용해 **학생 상태**를 만든다. 관리자는 한 화면에서
강의실 단위로 그 상태를 확인한다.

**이것은 얼굴 인식 시스템이 아니다.** 얼굴 인식은 학생을 식별하는 수단이고,
제품이 내놓는 것은 출결 판단에 쓸 수 있는 학생 상태다.

**식별과 위치를 서로 다른 카메라가 담당한다.** 입구 카메라가 얼굴로 신원을 한 번 정하고,
그 신원을 트래킹으로 이어 어안 CCTV에서 좌석을 판정한다
([결정 0024](../architecture/decisions.md#0024--카메라-구성을-전체-조망-cctv와-입구-카메라로-바꾸고-학생-식별을-입구-1회로-한정한다), [0025](../architecture/decisions.md#0025--강의실-안-신원-유지를-bytetrack-트래킹으로-하고-인계-실패는-unknown으로-둔다)).

## 배경

지금은 관리자가 직접 강의실에 들어가 확인한다. 확인 시점에만 알 수 있고, 기록이
남지 않으며, 강의실이 여러 개면 동시에 볼 수 없다.

카메라와 컴퓨터 비전으로 이를 대신하려면 세 가지가 필요하다 — 누구인지(식별),
어디 있는지(좌석), 지금 봐야 하는 시간인지(수업 시간). 셋 중 하나라도 빠지면
"사람이 한 명 있다"까지밖에 말할 수 없다.

**식별과 좌석은 한 화각에서 동시에 얻어지지 않는다.** 좌석이 다 보이는 화각에서는
얼굴이 인식하기에 너무 작고, 얼굴이 크게 잡히는 화각에서는 좌석이 보이지 않는다.
그래서 입구에서 신원을 얻고 트래킹으로 좌석까지 잇는다 — 이 잇는 일이 이 MVP의
가장 어려운 부분이다.

## 현재 구현 사실

| 대상 | 현재 사실 |
| --- | --- |
| `webapps/fastapi` | 강의실·좌석·학생·ROI 관리, 실시간 모니터링과 검색 화면. 인증 없음. memory / MongoDB 두 mode |
| 좌석 상태 | `OCCUPIED` / `VACANT` / `UNKNOWN`. **자리가 찼는지**를 뜻하며 **누가 앉았는지**가 아니다 |
| 좌석 관측 | batch 전체 선검증, event ID 멱등 처리, 오래된 관측은 현재 상태를 되돌리지 않음 |
| 모니터링·검색 | `DEMO_MODE_ENABLED=true`인 local/dev의 고정 합성 데이터. 실제 스트림·의미 검색이 아니다 |
| `worker/stream` | 다중 RTSP 수신·재연결·프레임 샘플링 |
| `worker/inference` | 입구는 얼굴 관측만, CCTV는 학습 YOLO·사람 ByteTrack만 실행. 입구 얼굴 신원을 CCTV track에 인계한 뒤 역할별 이벤트를 `FASTAPI_URL`로 전달 |
| `worker/recorder` | FFmpeg 세그먼트를 객체 저장소에 적재하고 보존 기간 경과분 삭제 |
| `deeplearning` | SCRFD·ArcFace 오픈셋 식별, 얼굴 track, MongoDB 대표 embedding 갤러리, MediaPipe 자세와 모델 비교 평가 하네스 구현 |
| 학생·얼굴·좌석 연동 | 입구 식별→CCTV ByteTrack→좌석 ROI 코드 경로 구현. 실제 문 ROI·가중치 배포 검증과 시간표 기반 `ABSENT`는 남음 |

입구 카메라 안에서는 얼굴 track에 `student_id`와 ArcFace similarity를 채운다([0040](../architecture/decisions.md#0040--입구는-얼굴-관측-cctv는-사람-추적으로-실행-경로를-분리한다)).
worker는 CCTV 문 영역에서 유일하게 새로 생긴 ByteTrack에만 그 신원을 인계하고, 같은
track이 유지되는 동안 좌석 ROI까지 전달한다([0036](../architecture/decisions.md#0036--문-영역과-통과-시각으로-입구-신원을-cctv-bytetrack에-보수적으로-인계한다)).
동시 입장처럼 후보가 모호하면 잘못 잇지 않고 `UNKNOWN`으로 둔다.
worker → FastAPI HTTP 전달과 FastAPI의 ROI·좌석 지정 기반 상태 판정은 구현됐다
([결정 0027](../architecture/decisions.md#0027--실시간-관제-전달을-httpwebrtcsse로-구성한다),
[결정 0019](../architecture/decisions.md#0019--실시간-학생-상태-연동은-카메라별-roi와-fastapi-판정을-사용한다)).

## 상태 정의

| 상태 | 성립 조건 | 범위 |
| --- | --- | --- |
| `PRESENT` | 학생이 식별됐고 현재 좌석이 지정 좌석과 같다 | MVP |
| `WRONG_SEAT` | 학생이 식별됐으나 현재 좌석이 지정 좌석과 다르다. 또는 지정 좌석에서 다른 학생이 식별됐다 | MVP |
| `ABSENT` | 수업 시간 중 지정 좌석에서 유예 시간을 넘겨 미식별 | MVP |
| `UNKNOWN` | 식별되지 않았거나 신뢰도가 기준 미만 | MVP. 상태가 아니라 **판정 불가**다 |
| `IN_CLASSROOM` | 신원 있는 track이 교실 안에 있으나 어느 좌석 ROI에도 없다 | MVP. 트래킹이 핵심 경로가 되어 편입됐다([0025](../architecture/decisions.md#0025--강의실-안-신원-유지를-bytetrack-트래킹으로-하고-인계-실패는-unknown으로-둔다)) |

판정 순서는 다음과 같다.

```text
수업 시간인가? ─NO─▶ 상태 판정을 하지 않는다
     │YES
     ▼
신원 있는 track인가? ─NO─▶ 미식별 지속이 유예 시간을 넘었는가?
     │YES                        ├─NO─▶ 이전 상태 유지
     ▼                            └─YES─▶ ABSENT
어느 좌석 ROI 안인가? ─NO─▶ IN_CLASSROOM
     │YES
     ▼
지정 좌석인가? ─YES─▶ PRESENT
     └─NO──▶ WRONG_SEAT
```

**미관측을 부재로 바꾸지 않는다.** 카메라가 끊겼거나 얼굴이 가려진 것과 학생이
자리에 없는 것은 다른 사실이다. 유예 시간을 넘긴 미식별만 `ABSENT`가 된다.

**신원 없는 track은 상태를 만들지 않는다.** track이 끊겼거나 카메라 간 인계에
실패했다는 뜻이며, 가장 가까운 학생에게 신원을 추정해 붙이지 않는다([0025](../architecture/decisions.md#0025--강의실-안-신원-유지를-bytetrack-트래킹으로-하고-인계-실패는-unknown으로-둔다)의 4번).

## 범위

**포함**

- 학생 원장 관리 — 등록, 조회, 수정, 비활성화
- 강의실 좌석에 학생을 지정하는 좌석 배치 관리
- 좌석 ROI 정의 — 카메라 화면상 좌석 영역
- 얼굴 등록 — 샘플 수집, 품질 판정, embedding 생성, Face Profile 저장
- 사람 트래킹과 카메라 간 신원 인계
- 탐지 결과 수신 내부 API
- 좌석 대조와 시간 정책을 적용하는 상태 판정
- 학생 상태 조회와 상태 이력
- 관리자 화면에서 강의실 단위 현황 확인
- 관리자의 상태 수동 보정

**제외 — 이후 단계에서 한다**

- 좌석 화각에서의 얼굴 인식 — 입구 식별과 트래킹으로 대신한다([0024](../architecture/decisions.md#0024--카메라-구성을-전체-조망-cctv와-입구-카메라로-바꾸고-학생-식별을-입구-1회로-한정한다))
- 카메라 추가와 다중 강의실 동시 운영
- LLM 기반 자연어 검색(현재 규칙 기반 검색은 유지한다)
- RPA — 미등원 확인, 보호자·담당자 알림, 일·주간 보고, 외부 시스템 갱신
- 학생·보호자용 로그인과 알림

**제외 — 이 프로젝트에서 하지 않는다**

- 모델 자동 재학습 파이프라인, 데이터셋 라벨링 도구 — 사람 탐지 모델의 수동 학습
  노트북은 `deeplearning/training/`에 있다([결정 0029](../architecture/decisions.md#0029--deeplearning에-모델-학습용-jupyter-노트북-도구를-둔다))
- 학생 원장·수업 시간표의 원본 관리(외부 시스템이 있다면 그쪽이 정본이다)
- 기존 출결 시스템의 대체

## 카메라 구성

MVP는 역할이 다른 카메라 2대를 쓴다([결정 0024](../architecture/decisions.md#0024--카메라-구성을-전체-조망-cctv와-입구-카메라로-바꾸고-학생-식별을-입구-1회로-한정한다)).

```text
강의실
├─ 어안 CCTV 1대   → 강의실 전체 조망. 좌석을 판정한다. 얼굴 인식을 하지 않는다
└─ 입구 카메라 1대 → 라즈베리파이 + 웹캠, RTSP 송출. 문쪽만 바라본다.
                     얼굴로 신원을 만든다. 좌석을 판정하지 않는다
```

**한 카메라가 두 일을 하지 않는다.** 입구 카메라의 탐지 이벤트는 좌석 점유·좌석 대조에
참여하지 않고, CCTV의 탐지 이벤트는 신원을 새로 만들지 않는다. 이 역할 구분이
[0020](../architecture/decisions.md#0020--좌석-위치-판정의-정본을-roi-하나로-통일한다)이
남겨 둔 "조망 카메라가 좌석 판정을 덮어쓰는 문제"를 해소한다.

**어안 왜곡 보정은 사람 탐지 이전에 한 번만 하고, 보정된 좌표계가 ROI와 bbox의 정본이다.**
원본 어안 좌표를 ROI에 쓰지 않는다. 보정 수행 위치는 `결정 필요`다.

**입구 부근 좌석에는 차폐가 있다.** 차폐 구간 좌석은 ROI를 등록하지 않아 `UNKNOWN`으로
남긴다. 보이지 않는 좌석의 상태를 추정하지 않는다.

**입구 카메라는 문쪽만 바라보게 둔다.** 얼굴을 가장 크고 정면에 가깝게 담기 위해서다.
그 결과 **두 카메라의 화각은 겹치지 않으며**, 이것이 신원 인계 방법의 선택지를 좁힌다
([0024](../architecture/decisions.md#0024--카메라-구성을-전체-조망-cctv와-입구-카메라로-바꾸고-학생-식별을-입구-1회로-한정한다)의 7번).

**배치의 나머지는 실제 촬영으로 확정한다.** 카메라 높이, 촬영 거리, 화각, 역광, 입구에서의
얼굴 크기, 차폐 범위, 그리고 **CCTV 화면상의 문 영역**을 확인한 뒤 정한다. 확정 전에는
특정 배치를 전제한 좌표 계산을 코드에 굳히지 않는다.

**작은 얼굴 문제는 카메라 역할 분리로 우회한다.** 얼굴 인식을 얼굴이 크게 잡히는 입구
에서만 하므로 Super Resolution 검토가 핵심 경로에서 빠졌다.

## 신원 유지와 카메라 간 인계

식별이 입구 한 번뿐이므로, 그 신원을 좌석까지 들고 가는 것이 이 MVP의 핵심 난제다
([결정 0025](../architecture/decisions.md#0025--강의실-안-신원-유지를-bytetrack-트래킹으로-하고-인계-실패는-unknown으로-둔다)).

```text
입구 카메라                              어안 CCTV
  얼굴 탐지 → 얼굴 track                    사람 탐지 → ByteTrack → track_id
       ↓                                        ↑
  얼굴 인식 → student_id                        │
       ↓                                        │
  얼굴 track에 student_id를 붙인다 ──인계────────┘
                                    ↑
                     문 영역 + 통과 시각의 유일 후보
```

- **신원은 학생이 아니라 track에 붙는다.** track이 유지되는 동안만 신원이 유지된다.
- **두 카메라는 추적 대상도 다르다.** 입구는 얼굴 track, CCTV는 사람 ByteTrack을 쓰고
  좌표계나 track ID 공간을 공유하지 않는다.
- **인계는 CCTV 문 영역과 입구 통과 시각을 함께 쓴다.** "문 앞에서 t에 식별된 학생"과
  "t 직후 CCTV 문 영역에서 처음 생긴 track"이 각각 하나일 때만 연결한다.
- **여러 명이 짧은 간격으로 들어오면 인계하지 않는다.** 후보 학생이나 신규 track이
  둘 이상이면 순서·거리로 추정하지 않고 `UNKNOWN`으로 둔다([0036](../architecture/decisions.md#0036--문-영역과-통과-시각으로-입구-신원을-cctv-bytetrack에-보수적으로-인계한다)).
- **track이 끊기거나 인계에 실패하면 `UNKNOWN`이다.** 가까운 track에 이어붙이지 않는다.
- **ID switch가 이 구조에서 가장 위험한 실패다.** 얼굴 인식은 틀려도 다음 프레임에서
  회복되지만, 트래킹은 한 번 어긋나면 확신을 가진 채 계속 틀린다. track 유실률·인계
  성공률·평균 track 수명을 지표로 노출한다.

## 도메인 구조 (`예정`)

[결정 0001](../architecture/decisions.md#0001--fastapi-계층형-구조와-경계-포트)의
기능별 디렉터리와 `router → service → port ← adapter` 규칙을 그대로 따른다.

```text
webapps/fastapi/app/
├─ classrooms/            기존. 좌석 ROI와 지정 좌석을 추가한다
├─ video_monitoring/      기존. 학생 상태 판정 책임을 갖지 않는다
├─ students/              신규
├─ face_enrollment/       신규
├─ student_monitoring/    신규
└─ shared/                기존
```

각 신규 도메인은 `router.py`, `service.py`, `schemas.py`, `models.py`, `ports.py`,
`errors.py`, `adapters/`로 구성한다. **구현체가 하나뿐인 추상화를 만들지 않는다.**
새 포트는 프로세스 밖으로 나가는 I/O일 때만 만든다
([결정 0002](../architecture/decisions.md#0002--설계-패턴-적용-범위와-판단-기준)).

| 도메인 | 책임 | 여기에 두지 않는 것 |
| --- | --- | --- |
| `students` | 학생 원장 — 식별자, 학번, 이름, 소속 강의실, 활성 여부, 동의 상태 | 얼굴 데이터, 출결 판정 |
| `classrooms` | 강의실, 좌석, 좌석 ROI, 좌석-학생 지정, 좌석 점유 관측 | 학생 신원 판정 |
| `face_enrollment` | 등록 세션, 샘플 품질 판정, embedding 생성 호출, Face Profile | 실시간 인식, 상태 판정 |
| `student_monitoring` | 탐지 이벤트 수신, 좌석 대조, 시간 정책, 학생 상태와 이력 | 모델 호출, 영상 저장, **트래킹과 신원 인계**(worker/deeplearning 경계의 일이다) |
| `video_monitoring` | 영상 source 목록과 상태, 검색 | 학생 상태 판정 |

**`student_monitoring`이 두 개 이상의 기능 디렉터리를 가로지른다.** 학생, 좌석,
얼굴 프로필을 함께 읽으므로 이 도메인의 `service.py`가 그 조합의 파사드가 된다.
`facade.py` 같은 파일을 만들지 않는다.

## API 계약 (`예정`)

형식은 [API 규칙](../conventions/api-convention.md)을 따른다. 아래는 목표 계약이며,
구현 후에는 자동 생성 OpenAPI가 정본이다.

### 학생

| 메서드 | 경로 | 용도 |
| --- | --- | --- |
| `GET` | `/api/v1/students` | 학생 목록. `limit`·`offset`·`classroom_id` |
| `POST` | `/api/v1/students` | 학생 등록 |
| `GET` | `/api/v1/students/{student_id}` | 학생 상세 |
| `PATCH` | `/api/v1/students/{student_id}` | 학생 수정·비활성화 |

### 좌석과 지정

| 메서드 | 경로 | 용도 |
| --- | --- | --- |
| `GET` | `/api/v1/classrooms/{classroom_id}/seats` | 좌석 목록과 ROI, 지정 학생 |
| `PUT` | `/api/v1/classrooms/{classroom_id}/seats/{seat_id}/assignment` | 좌석에 학생 지정·해제 |

`GET /api/v1/classrooms`와 `GET /api/v1/classrooms/{classroom_id}/occupancy`는
현재 구현된 계약이다. **응답 필드를 지우거나 이름을 바꾸는 것은 깨는 변경이다.**
학생 정보는 필드 추가로 붙인다.

### 얼굴 등록

| 메서드 | 경로 | 용도 |
| --- | --- | --- |
| `POST` | `/api/v1/students/{student_id}/face-enrollments` | 등록 세션 시작·샘플 제출 |
| `GET` | `/api/v1/face-enrollments/{enrollment_id}` | 등록 세션 상태와 품질 판정 결과 |
| `DELETE` | `/api/v1/face-enrollments/{enrollment_id}` | 등록 세션 취소 |
| `GET` | `/api/v1/students/{student_id}/face-profile` | 등록 완료 여부와 메타데이터 |

**얼굴 원본 이미지와 embedding 값을 응답 본문에 넣지 않는다.** 등록 여부, 샘플 수,
품질 판정 결과, 모델 버전, 등록 시각까지만 돌려준다.

### 탐지 결과 수신 (내부)

```text
POST /internal/inference/events
```

```json
{
  "camera_id": "classroom-cctv",
  "captured_at": "2026-08-11T09:03:00Z",
  "detections": [
    {
      "track_id": "cctv-7",
      "student_id": "student_001",
      "identity_confidence": 0.87,
      "person_bbox": [100, 120, 300, 600],
      "face_bbox": null
    }
  ]
}
```

- **`/api/v1`이 아니라 `/internal`에 둔다.** 브라우저가 부르는 경로가 아니다.
- **batch로 받는다.** 프레임 한 장의 탐지 결과를 통째로 넘긴다.
- **`event_id`로 멱등 처리한다.** 같은 이벤트가 두 번 들어와도 상태가 두 번 바뀌지 않는다.
- **식별에 실패한 탐지도 보낸다.** `student_id`가 `null`이면 미식별이며, 좌석이
  비어 있다는 뜻이 아니라 누구인지 모른다는 뜻이다.
- **`track_id`는 카메라 안에서만 유효하다.** 다른 카메라의 같은 값이 같은 사람을
  뜻하지 않는다. 두 카메라의 track을 잇는 것은 신원 인계의 일이다([0025](../architecture/decisions.md#0025--강의실-안-신원-유지를-bytetrack-트래킹으로-하고-인계-실패는-unknown으로-둔다)).
- **CCTV의 탐지에는 `face_bbox`가 없다.** 좌석 화각에서 얼굴 인식을 하지 않는다.
- `track_id`는 기존 계약에 대한 **필드 추가**이므로 깨는 변경이 아니다.
- `worker/inference`가 HTTP로 이 경로를 호출한다
  ([결정 0027](../architecture/decisions.md#0027--실시간-관제-전달을-httpwebrtcsse로-구성한다)).
  timeout·재시도·전송 버퍼와 내부 인증은 구현 계약에서 정한다.

### 학생 상태

| 메서드 | 경로 | 용도 |
| --- | --- | --- |
| `GET` | `/api/v1/classrooms/{classroom_id}/student-states` | 한 강의실의 현재 학생 상태 |
| `GET` | `/api/v1/students/{student_id}/state-history` | 한 학생의 상태 이력. 기간·페이지네이션 |
| `POST` | `/api/v1/student-state-evaluations` | 시간 정책의 명시적 평가 |
| `PATCH` | `/api/v1/students/{student_id}/state` | 관리자 수동 보정 |

**`GET`은 상태를 바꾸지 않는다.** 유예 시간 경과에 따른 `ABSENT` 전이는 명시적
평가 요청이나 탐지 이벤트 수신에서만 일어난다. 조회가 부작용을 일으키면 화면을
두 번 연 것과 한 번 연 것의 결과가 달라진다.

## 화면 계약 (`예정`)

관리자 화면은 세 개를 유지하고, 강의실 화면에 학생 상태를 더한다.
관리 화면(학생·좌석 지정·얼굴 등록)은 별도로 추가한다.

| 화면 | 경로 | 필수 내용 |
| --- | --- | --- |
| 강의실 현황 | `/classrooms` | 강의실 선택, 좌석 지도, 좌석별 지정 학생과 상태, 재석·잘못된 자리·부재·확인 필요 집계, 마지막 관측 시각 |
| 실시간 모니터링 | `/monitoring` | 카메라별 영상 영역, 연결 상태, 마지막 상태 시각, demo 여부 |
| 검색 | `/video-search` | 검색 문장과 기간·강의실 조건, 결과와 일치 이유 |
| 학생 관리 | `/students` | 학생 목록·등록, 얼굴 등록 여부 |
| 좌석 지정 | `/classrooms/seat-assignments` | 좌석에 학생 지정·해제 |
| 얼굴 등록 | `/students/{student_id}/face-enrollment` | 샘플 수집, 품질 판정 결과, 등록 완료 |

화면 규칙:

- **템플릿에 비즈니스 판단을 두지 않는다.** 상태 판정과 신뢰도 등급 해석은
  서비스에서 끝내고 템플릿에는 결과만 넘긴다.
- **상태를 색으로만 구분하지 않는다.** 문구와 기호를 함께 쓴다.
- **정상·빈 상태·오류 상태를 모두 만든다.** "데이터 없음"과 "조회 실패"를 구분한다.
- **미식별을 부재로 표시하지 않는다.** `UNKNOWN`은 "확인 필요"로 보여 준다.
- **얼굴 원본 이미지를 화면에 노출하지 않는다.** 등록 화면에서 관리자가 방금 찍은
  샘플을 확인하는 경우만 예외이며, 저장된 이미지를 목록으로 보여 주지 않는다.

## 설정 (`예정`)

값의 취급과 명명 규칙은 [환경변수 규칙](../conventions/environment-convention.md)을 따른다.

| 이름 | 용도 | 비고 |
| --- | --- | --- |
| `IDENTITY_CONFIDENCE_THRESHOLD` | 이 값 미만의 식별은 `UNKNOWN` | 실제 촬영으로 정한다 |
| `ABSENCE_GRACE_PERIOD_SECONDS` | 미식별이 이만큼 이어지면 `ABSENT` | **값 `결정 필요`** (5/10/20/30분 후보) |
| `SEAT_MATCH_TOLERANCE` | 좌석 ROI 판정 여유 | 판정 방식 확정 후 |
| `TRACK_STALE_SECONDS` | 이 시간 갱신이 없으면 track을 끊긴 것으로 본다 | 실제 촬영으로 정한다 |
| `IDENTITY_HANDOVER_ROUTES` | 입구·CCTV camera ID와 CCTV 문 영역 | 배치별 `.env`; 실제 화면으로 보정 |
| `IDENTITY_HANDOVER_*` | 인계 시간 창·clock skew·track stale·신뢰도 | 실제 통과 영상으로 조정 |
| `FACE_ENROLLMENT_MIN_SAMPLES` | 등록에 필요한 최소 샘플 수 | |
| `FACE_QUALITY_MIN_SIZE_PIXELS` | 등록 샘플의 최소 얼굴 크기 | |

기존 `SEAT_OCCUPANCY_CONFIDENCE_THRESHOLD`는 좌석 점유 관측용으로 유지한다.
학생 식별 신뢰도와 다른 값이므로 하나로 합치지 않는다.

## 사용자 흐름

1. 관리자가 학생을 등록한다.
2. 그 학생의 얼굴을 등록한다. 샘플이 품질 기준에 미달하면 다시 찍는다.
3. 강의실 좌석에 학생을 지정한다.
4. 학생이 입구를 지나면 얼굴로 신원이 정해지고, 그 신원이 CCTV의 track으로 이어진다.
5. 학생이 앉으면 그 track의 위치가 좌석 ROI와 대조된다.
6. 관리자가 강의실 현황 화면에서 재석·잘못된 자리·교실 내 이동·부재·확인 필요를 확인한다.
7. 판정이 실제와 다르거나 입구에서 식별을 놓쳤으면 근거 이벤트를 확인하고 수동 보정한다.

**6번까지는 사람이 개입하지 않고, 7번은 사람만 한다.**

## 요구사항

| 번호 | 요구사항 | 필수 여부 |
| --- | --- | --- |
| R1 | 관리자가 학생을 등록·조회·수정·비활성화할 수 있다 | 필수 |
| R2 | 관리자가 좌석에 학생을 지정하고 해제할 수 있다 | 필수 |

| R5 | 탐지 결과를 batch로 수신하고 `event_id`로 멱등 처리한다 | 필수 |

| R7 | 수업 시간 중 유예 시간을 넘긴 미식별을 `ABSENT`로 판정한다 | 필수 |
| R8 | 수업 시간이 아니면 상태 판정을 수행하지 않는다 | 필수 |
| R9 | 신뢰도 미달 식별을 `UNKNOWN`으로 두고 이름을 붙이지 않는다 | 필수 |
| R10 | 미관측·조회 실패를 `ABSENT`로 표시하지 않는다 | 필수 |
| R11 | 상태 전이를 이력으로 남기고 근거 탐지 이벤트를 참조할 수 있다 | 필수 |
| R12 | 관리자가 상태를 수동 보정할 수 있고 보정 기록이 남는다 | 필수 |
| R13 | 조회 GET이 저장된 상태를 바꾸지 않는다 | 필수 |
| R14 | 판정 기준값이 코드가 아니라 설정으로 주입된다 | 필수 |
| R15 | 탐지 결과 스키마와 추론 코드에 `PRESENT` 같은 업무 어휘가 없다 | 필수 |
| R16 | 얼굴 embedding과 원본 이미지가 API 응답·로그·화면 목록에 노출되지 않는다 | 필수 |
| R17 | 강의실 현황 화면이 상태를 색 외의 문구·기호로 구분한다 | 필수 |
| R18 | 세 신규 도메인이 기존 계층 규칙(`router → service → port ← adapter`)을 따른다 | 필수 |
| R19 | 얼굴 프로필을 학생 단위로 삭제할 수 있다 | 필수 |

| R23 | 신원 있는 track이 좌석 ROI 밖에 있으면 `IN_CLASSROOM`으로 판정한다 | 필수 |
| R24 | 입구 카메라 이벤트가 좌석 판정에, CCTV 이벤트가 신원 생성에 참여하지 않는다 | 필수 |
| R25 | 어안 보정된 좌표계 하나만 ROI·bbox 판정에 쓰인다 | 필수 |
| R26 | track 유실률·인계 성공률·평균 track 수명이 지표로 노출된다 | 필수 |
| R27 | 입구에서 식별을 놓친 학생을 관리자가 수동 지정할 수 있다 | 필수 |

## 완료 조건

- [ ] 학생 등록 → 얼굴 등록 → 좌석 지정 → **입구 통과 식별** → 착석 → `PRESENT` 표시가
      어안 CCTV 1대 + 입구 카메라 1대로 동작한다
- [ ] 입구에서 식별한 학생이 CCTV에서 같은 사람으로 이어진다(카메라 간 인계 성공)
- [ ] 신원 있는 학생이 좌석을 떠나 교실 안에 있으면 `IN_CLASSROOM`으로 표시된다
- [ ] track이 끊긴 사람에게 다른 학생의 이름이 붙지 않는다
- [ ] 어안 보정 전 좌표로 ROI를 판정하는 경로가 코드에 없다
- [ ] 지정 좌석이 아닌 자리에 앉으면 `WRONG_SEAT`으로 표시된다
- [ ] 수업 시간 중 유예 시간을 넘겨 미식별이면 `ABSENT`로 전이된다
- [ ] 수업 시간이 아닐 때 상태 판정이 수행되지 않는다
- [ ] 카메라를 끊었을 때 `ABSENT`가 아니라 확인 필요 상태가 표시된다
- [ ] 신뢰도 미달 식별이 `UNKNOWN`으로 남는다
- [ ] 같은 탐지 이벤트를 두 번 보내도 상태와 이력이 한 번만 바뀐다
- [ ] 상태 이력에서 각 전이의 근거 이벤트를 찾을 수 있다
- [ ] 관리자 수동 보정이 반영되고 기록이 남는다
- [ ] 얼굴 프로필 삭제 후 해당 학생이 식별되지 않는다
- [ ] API 응답·로그·화면 어디에도 embedding과 얼굴 원본이 노출되지 않는다
- [ ] `python -m ruff check app tests`가 통과한다
- [ ] `python -m ruff format --check app tests`가 통과한다
- [ ] `python -m mypy app tests`가 통과한다
- [ ] `python -m pytest -q`가 통과한다

## 영향 범위

| 대상 | 영향 |
| --- | --- |
| `webapps/fastapi` | 기능 디렉터리 3개 추가, `classrooms` 확장, 화면 추가 |
| API 계약 | 추가. 기존 `classrooms` 응답은 **필드 추가만** 한다. 삭제·이름 변경은 깨는 변경 |
| 데이터 | MongoDB 컬렉션 8개 추가. **얼굴 데이터는 별도 권한 경계가 필요하다** |
| `deeplearning` | SCRFD·ArcFace 갤러리 식별과 얼굴 track 구현. 외형 re-ID·homography 인계는 실험 코드로 유지 |
| `worker/inference` | 카메라별 사람 ByteTrack, 입구 얼굴 식별, 문 영역·시각 기반 CCTV 신원 인계와 `track_id`·신원 전달 구현 |
| `worker/stream` | 어안 CCTV 수신 추가. 왜곡 보정을 여기서 할지 `결정 필요` |
| 입구 카메라 노드 | 라즈베리파이 + 웹캠의 RTSP 송출 구성. 저장소에 코드가 없다 |
| `monitoring` | track 생성·만료·활성 수, track 수명, 인계 결과 지표 구현. 대시보드·경보는 남음 |
| 개인정보 | **동의·보존·접근 권한 합의가 선행되어야 한다** |

## 예외와 실패 상황

| 상황 | 기대 동작 |
| --- | --- |
| 얼굴이 등록되지 않은 학생 | 식별 대상에서 제외하고, 화면에 "얼굴 미등록"을 구분해 표시한다 |
| 등록 샘플이 품질 기준 미달 | 등록을 완료하지 않고 어떤 기준에 미달했는지 알린다 |
| 식별 신뢰도가 기준 미만 | `UNKNOWN`으로 두고 가장 가까운 학생 이름을 붙이지 않는다 |
| 한 프레임에 같은 학생이 두 곳에서 식별됨 | 신뢰도가 높은 쪽만 채택하고 나머지는 이력에 기록한다 |
| 지정 좌석에 다른 학생이 식별됨 | 두 학생 모두 `WRONG_SEAT` 후보로 다루고 관리자 확인 대상으로 표시한다 |
| 카메라 연결이 끊김 | 해당 카메라 담당 좌석을 확인 필요로 두고 `ABSENT`로 전이하지 않는다 |
| 입구 카메라가 끊김 | 새로 들어오는 학생의 신원을 만들 수 없다. 이미 인계된 track은 유지된다. 화면에 식별 불가 상태를 표시한다 |
| CCTV track이 끊김 | 그 사람은 신원 없는 사람이 된다. 다시 잡힌 track에 이전 신원을 추정해 붙이지 않는다 |
| 카메라 간 인계에 실패 | CCTV track을 신원 없이 두고 좌석 판정 근거로 쓰지 않는다. 좌석 점유는 여전히 관측한다 |
| 여러 명이 동시에 입구를 통과 | 얼굴이 확실히 잡힌 사람만 신원을 만든다. 통과 순서로 나머지를 추정하지 않는다 |
| 입구 차폐로 얼굴을 놓침 | 그 학생은 신원 없이 남는다. 관리자 수동 지정으로만 회복한다 |
| ID switch가 의심됨 | 자동으로 되돌리지 않는다. 지표로 드러내고 관리자 확인 대상으로 표시한다 |
| 어안 보정 파라미터가 없거나 틀림 | 좌석 판정을 수행하지 않는다. 보정되지 않은 좌표로 ROI를 판정하지 않는다 |
| 탐지 이벤트가 오래된 시각을 가짐 | 현재 상태를 되돌리지 않는다. 이력에는 남긴다 |
| 같은 `event_id` 재수신 | 200을 반환하고 상태를 다시 바꾸지 않는다 |
| 수업 시간표가 없음 | 상태 판정을 수행하지 않고 그 사실을 화면에 표시한다 |
| 저장소를 사용할 수 없음 | 부분 데이터로 대체하지 않고 503을 반환한다 |
| 얼굴 프로필 삭제 요청 | embedding과 원본 이미지를 함께 지우고 삭제 기록을 남긴다 |

## 구현 순서

1. **실제 촬영** — 어안 CCTV와 입구 카메라를 배치하고 입구에서의 얼굴 크기, 입구 차폐
   범위, 어안 보정 후 좌석 영역의 형태, **CCTV 화면상의 문 영역**과 문을 지나 좌석까지
   가는 동안의 track 유지 여부를 확인한다. 이 결과 없이 좌석 판정 방식·임계값과
   **카메라 간 신원 인계 방법**을 정하지 않는다.
1-1. **어안 보정** — 캘리브레이션 파라미터를 확보하고 보정 수행 위치를 정해 결정으로
   기록한다. 이후 모든 좌표 작업이 보정된 좌표계 위에서 이뤄진다.
2. **학생·좌석 도메인** — `students`와 `classrooms`의 좌석 지정·ROI.
   모델 없이 완결되므로 먼저 한다.
3. **얼굴 등록** — 품질 판정 규칙과 등록 흐름. embedding 생성은 `deeplearning`에 위임한다.
4. **모델 비교** — 얼굴 탐지기와 인식 모델 후보를 같은 조건으로 비교하고 결정을 기록한다.
5. **`worker` → `deeplearning` 연결** — 모델 호출을 이관한다.
5-1. **트래킹 실측** — 구현된 CCTV ByteTrack의 ID switch·유실 구간을 실제 영상으로 측정한다.
5-2. **카메라 간 신원 인계 보정** — CCTV 문 ROI와 시간 창을 실제 통과 영상으로 확정하고 동시 입장 실패율을 측정한다.
6. **탐지 결과 → `fastapi` 연결** — 전달 방식을 확정하고 수신 API를 만든다.
7. **좌석 대조** — 위치와 좌석 ROI로 현재 좌석을 정한다.
8. **상태 판정** — 지정 좌석 비교와 시간 정책을 붙여 상태를 완성한다.
   `IN_CLASSROOM`을 포함한다.
9. **화면** — 강의실 현황에 학생 상태를 붙이고 관리 화면을 추가한다.

각 단계가 끝날 때 그 단계까지의 흐름을 실제로 실행해 확인한다.
**모델이 없어도 2·3단계는 memory mode에서 완결되어야 한다.**

## 미결정 사항

정본은 [아키텍처의 미결정 항목](../architecture/README.md#미결정-항목)이다.
아래는 그중 이 명세의 구현을 직접 막는 것만 추린 것이다.

| 항목 | 구현을 막는가 |
| --- | --- |
| 얼굴 데이터 정책 — 동의 절차, 원본 보관 여부, 보존 기간, 접근 권한, 삭제 | **얼굴 등록 구현을 막는다** |
| 운영 접근 통제 방식 | local·dev 구현은 막지 않지만 **prod 배포를 막는다** |
| 얼굴 탐지·인식 모델 선정 | 실제 식별을 막는다. 도메인 구현은 막지 않는다 |
| 결석 유예 시간 값 | 완료 조건 검증을 막는다. 설정 구조는 막지 않는다 |
| 좌석 판정 방식(중심점·하단점 / ROI 겹침 비율) | 좌석 대조 구현을 막는다. 실제 촬영이 선행되어야 한다 |
| 수업 시간표의 원본 관리 주체 | 시간 정책 구현을 막는다 |
| 카메라 배치 확정 | 임계값 확정을 막는다 |
