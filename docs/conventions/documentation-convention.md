# 문서 작성 규칙

**목적**: 저장소의 문서가 서로 충돌하거나 중복되지 않게 하는 최소 규칙을 정한다.
**대상 독자**: 문서를 쓰거나 고치는 모든 사람과 AI 에이전트.

문서를 쓰는 절차는 `update-documentation` 스킬에,
문서 담당 에이전트의 규칙은 [documentation-agent](../agents/documentation-agent.md)에 있다.
이 문서는 **문서의 형식과 배치 기준**만 다룬다.

## 형식

- Markdown으로 쓴다.
- 파일 이름은 소문자와 하이픈을 쓴다: `local-development.md`
  예외는 관례를 따르는 `README.md`, `AGENTS.md`, `SKILL.md`, `ADR-NNNN-*.md`다.
- 제목(`#`)은 문서당 하나만 쓴다.
- 표와 목록을 적극적으로 쓴다. 같은 내용을 문단으로 늘어놓지 않는다.

## 문서 첫머리

모든 문서는 시작 부분에서 **목적과 대상 독자**를 밝힌다.

```markdown
# 로컬 개발 가이드

**목적**: 개발자 PC에서 서비스를 실행하는 방법을 안내한다.
**대상 독자**: 이 저장소에서 처음 개발을 시작하는 팀원.
```

READMEs처럼 대상이 자명한 문서는 한 줄 설명으로 대신해도 된다.
다만 "이 문서는 무엇을 답하는가"가 첫 화면에서 보여야 한다.

## 배치 기준

새 문서를 어디에 둘지는 아래로 판단한다.

| 답하는 질문 | 위치 |
| --- | --- |
| 이 저장소는 무엇인가 | 루트 `README.md` |
| 이 서비스는 무엇을 맡는가 | `webapps/<service>/README.md` |
| 시스템이 어떻게 구성되는가 | `docs/architecture/` |
| 왜 이렇게 결정했는가 | `docs/architecture/decisions/` |
| 결과물이 어떤 형식이어야 하는가 | `docs/conventions/` |
| 이 작업을 어떤 순서로 하는가 | `.claude/skills/` (저장소 밖) |
| 에이전트가 무엇을 지켜야 하는가 | `docs/agents/` |
| 에이전트에게 어떻게 지시하는가 | `docs/prompts/` |
| 처음 접하는 사람이 어떻게 시작하는가 | `docs/guides/` |
| 새 문서를 어떤 뼈대로 쓰는가 | `docs/templates/` |

주제별 기준 문서는 [AGENTS.md의 Source of Truth](../agents/AGENTS.md#source-of-truth)에 정리되어 있다.

## 중복 금지

**같은 정보를 두 문서에 쓰지 않는다.** 기준 문서 한 곳에 두고 나머지는 링크한다.

복사된 내용은 반드시 한쪽만 갱신되어 서로 다른 말을 하게 된다.
읽는 사람은 어느 쪽이 맞는지 알 수 없다.

- 규칙은 `conventions`에 한 번만 쓰고, Agent·Skill 문서는 링크한다.
- 서비스의 책임은 해당 README에만 쓰고, 아키텍처 문서는 관계만 다룬다.
- 링크가 길어지는 것이 복사보다 낫다.

## 링크

- **저장소 기준 상대 경로**로 쓴다: `../conventions/api-convention.md`
- 절대 경로, 로컬 파일 경로(`C:\...`), 저장소 호스팅 URL을 쓰지 않는다.
- 링크 텍스트는 문서 제목이나 내용을 드러내게 쓴다. `여기`, `이 문서`를 쓰지 않는다.
- 파일을 옮기거나 지우면 참조하던 문서를 모두 고친다.
- 새 문서를 만들면 관련 문서에서 링크를 건다. 어디서도 닿지 않는 문서는 읽히지 않는다.

## 사실과 계획의 구분

문서에서 세 가지를 섞지 않는다.

| 표기 | 의미 |
| --- | --- |
| (표기 없음) | 사실. 지금 그렇게 동작한다 |
| `예정` | 하기로 했으나 아직 구현되지 않았다 |
| `후보` | 고려 중인 선택지다 |
| `결정 필요` | 아직 정하지 않았다 |

- **확인하지 않은 동작을 사실처럼 쓰지 않는다.**
- **실행해 보지 않은 명령을 문서에 넣지 않는다.** 구현이 없으면 "구현 후 기록한다"고 적는다.
- 확정되면 표기를 지우고, 결정 근거는 [ADR](../architecture/decisions/README.md)에 남긴다.

## 쓰지 않는 것

- **변경 날짜, 작성자 서명, 버전 표기.** Git 이력이 관리한다.
- **내용 없는 절.** 쓸 것이 없으면 그 절을 만들지 않는다.
- **일반론.** "좋은 코드를 작성한다", "협업이 중요하다" 같은 문장은 지운다.
- **자리 채우기용 예시.** 실제로 쓸 수 없는 예시는 없느니만 못하다.

## Mermaid 사용

관계나 흐름이 글로 설명하기 어려울 때만 쓴다.

- **구조를 보여줄 때 쓴다.** 목록으로 충분한 것을 다이어그램으로 만들지 않는다.
- 노드 개수를 10개 내외로 유지한다. 넘으면 관심사별로 나눈다.
- **미확정 관계는 점선(`-.->`)으로 구분하고 범례를 단다.**
- 다이어그램이 설명하는 내용을 글로도 요약한다. 그림만 보고 판단하게 하지 않는다.
- 다이어그램과 문서 본문이 어긋나지 않게 함께 갱신한다.

사용 예는 [시스템 컨텍스트](../architecture/system-context.md)와
[아키텍처 개요](../architecture/overview.md)에 있다.
