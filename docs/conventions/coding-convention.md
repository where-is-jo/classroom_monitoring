# 코딩 규칙

**목적**: 언어와 무관하게 지킬 원칙과, Python·TypeScript에 각각 적용할 기본 규칙을 정한다.
**대상 독자**: 이 저장소에 코드를 쓰는 모든 사람과 AI 에이전트.

포매팅은 도구에 맡긴다. 이 문서는 도구가 잡아주지 않는 것만 다룬다.

## 공통 원칙

### 이름

- **무엇인지 드러나는 이름을 쓴다.** `data`, `temp`, `result`, `handle`은 대부분 더 나은 이름이 있다.
- 축약하지 않는다. `cfg`보다 `config`, `res`보다 `response`.
  단, 그 분야에서 통용되는 축약은 쓴다: `id`, `url`, `api`.
- **단위를 이름에 넣는다.** `timeout` 대신 `timeout_seconds`, `size` 대신 `size_bytes`.
  이 규칙 하나가 단위 착오로 인한 버그를 대부분 막는다.
- 불리언은 참일 때의 상태로 짓는다: `is_active`, `has_permission`.
  부정형 이름(`is_not_ready`)은 쓰지 않는다. 조건문에서 이중 부정이 된다.

### 함수

- **한 함수는 한 가지 일을 한다.** 함수 설명에 "그리고"가 들어가면 나눌 수 있다.
- 길이보다 **추상화 수준의 일관성**이 기준이다. 한 함수 안에서 고수준 흐름과
  저수준 문자열 조작이 섞이면 나눈다.
- 인자가 4개를 넘으면 묶을 수 있는지 본다.
- 불리언 인자로 동작을 분기하지 않는다. 함수를 나눈다.

### 구조

- **비즈니스 로직을 프레임워크 코드에서 분리한다.**
  라우터·컴포넌트·핸들러 안에 판단 로직을 두지 않는다.
- 판단 기준(임계값, 재시도 횟수, 주기)은 설정으로 뺀다.
- 같은 코드가 세 번째 나타나면 공통화를 검토한다. 두 번째는 아직 아니다.

### 오류

- **오류를 조용히 삼키지 않는다.** `except: pass`, 빈 `catch`를 쓰지 않는다.
- 무시해도 되는 오류라면 왜 무시해도 되는지 주석으로 남긴다.
- 예외를 잡을 때는 잡아야 할 것만 잡는다. 광범위한 예외 포착으로 버그를 가리지 않는다.
- 실패를 기본값으로 대체해 넘기지 않는다. 호출자가 실패를 알 수 있어야 한다.

### 설정과 비밀값

- **설정값을 하드코딩하지 않는다.** 주소, 포트, 임계값, 경로, 타임아웃이 해당한다.
- **로그에 비밀정보를 기록하지 않는다.** 토큰, 비밀번호, 인증 헤더, 개인정보.
  객체를 통째로 로그에 찍을 때 안에 무엇이 들어 있는지 확인한다.
- 외부 호출에는 항상 타임아웃을 지정한다.

### 주석

- **무엇을 하는지가 아니라 왜 그렇게 했는지 쓴다.**
  코드를 읽으면 아는 내용을 반복하지 않는다.
- 비직관적인 처리, 우회 방법, 외부 시스템의 제약을 설명하는 주석은 가치가 있다.
- 주석 처리한 코드를 남기지 않는다. Git에 남아 있다.

## Python

- **타입 힌트를 붙인다.** 공개 함수의 인자와 반환값은 예외 없이.
- 가변 기본 인자(`def f(items=[])`)를 쓰지 않는다.
- 경로는 문자열 조합 대신 `pathlib`을 쓴다.
- 자원은 `with`로 관리한다.
- 예외는 표준 예외를 쓰되, 도메인 구분이 필요하면 명시적인 예외 클래스를 정의한다.
- 모듈 최상위에서 무거운 작업(모델 로딩, 네트워크 호출)을 하지 않는다.
  import만으로 부작용이 생기면 테스트가 어려워진다.
- 서비스 계층에서 웹 프레임워크 타입을 쓰지 않는다.
  자세한 내용은 [backend-agent](../agents/backend-agent.md)에 있다.

## TypeScript

- **`any`를 쓰지 않는다.** 타입을 모르겠으면 `unknown`으로 받고 좁힌다.
- 외부 응답을 타입 단언(`as`)으로 통과시키지 않는다. 실제 형태를 확인해 타입을 정의한다.
- `strict` 모드를 켠다.
- 옵셔널 체이닝으로 오류를 숨기지 않는다. 값이 없을 수 있다면 없을 때의 동작을 명시한다.
- 열거 가능한 값은 유니온 타입으로 좁힌다: `type Status = "active" | "error"`.
- 비동기 함수의 실패 경로를 처리한다. 처리하지 않은 Promise 거부를 남기지 않는다.
- API 응답 타입을 컴포넌트마다 따로 정의하지 않는다. 클라이언트 계층에 한 번 정의한다.

## 테스트

- 변경한 동작에는 테스트를 남긴다.
- **테스트를 통과시키려고 테스트를 약화시키지 않는다.**
- 실패 케이스를 테스트한다. 성공 경로만 검증하는 테스트는 절반이다.
- 테스트가 외부 서비스·실제 장비·모델 파일을 요구하면 별도로 표시해 기본 실행에서 분리한다.
