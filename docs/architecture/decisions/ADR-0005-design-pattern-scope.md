# ADR-0005: 설계 패턴 적용 범위와 판단 기준

## Status

Accepted

## Context

[ADR-0002](./ADR-0002-fastapi-layered-with-ports.md)가 계층 구조와 경계 포트를 정했다.
그러나 그 계층 **안에서** 어떤 설계 패턴을 언제 쓰는지는 정하지 않았다.
기능이 늘어나면 이 판단이 매번 필요해진다.

두 가지 상황이 이 결정을 앞당긴다.

**코드의 상당 부분을 AI 에이전트가 생성한다.** AI는 설계 패턴을 교과서적으로 정확하게,
그리고 **과하게** 만든다. 지시하지 않아도 인터페이스와 팩토리와 디스패처를 붙인다.
결과물은 개별적으로는 흠이 없지만, 팀원이 처음 파일을 열었을 때 실제 동작에 닿기까지
거쳐야 할 단계가 늘어난다. 이 프로젝트의 위험은 패턴이 부족한 것이 아니라
**필요해지기 전에 추상화가 먼저 들어오는 것**이다.

**적용 후보로 거론된 패턴 중 절반은 이미 있다.** `app/events/ports.py`의
`EventRepository`가 Repository이고, `app/shared/dependencies.py`가 조립을 한곳에 모은
Composition Root이며, `EventService`는 라우터에 대해 이미 파사드로 동작한다.
이들을 "새로 도입"하면 같은 것에 이름이 두 개 생긴다.

여기에 어휘 문제가 겹친다. 이 저장소의 문서와 코드는 GoF 패턴 이름을 한 번도 쓰지 않고
**포트·어댑터·서비스·조립**이라는 어휘로만 구조를 서술해 왔다. ADR-0002는 "새로 배울
개념이 `typing.Protocol`과 의존성 주입 두 가지로 한정된다"를 명시적인 이점으로 적었다.
GoF 이름을 코드와 문서에 1급 어휘로 들이면 그 이점이 사라진다.

한편 지금 상태에서 각 패턴을 실제로 만들면 어떻게 되는지는 이미 확인할 수 있다.

- 기능 디렉터리가 `events` 하나뿐이라 **파사드는 서비스로의 얇은 위임 껍데기**가 된다.
- Strategy의 유일한 후보인 신뢰도 등급 분류는 임계값 비교 `if` 세 줄이고
  **변형이 하나뿐**이다.
- Observer가 전달할 도메인 이벤트에 붙을 반응은 **아직 하나도 없다.**

게다가 Observer는 [아키텍처 개요의 미결정 항목](../overview.md#미결정-항목) 중
"서비스 간 통신 방식(동기 HTTP / 메시지 큐)"과 "실시간 화면 갱신 방식"에 직접 걸린다.
지금 인프로세스 이벤트 메커니즘을 만들면, 나중에 메시지 큐가 확정될 때 성격이 다른
이벤트 경로가 두 개 공존하게 된다.

따라서 지금 필요한 것은 패턴을 도입하는 결정이 아니라,
**언제 도입해도 되는지를 판정하는 기준**이다.

## Decision

**설계 패턴은 아래 표에 있는 것만, 표에 적힌 조건을 모두 만족할 때만 만든다.**
어휘는 기존의 포트·어댑터·서비스·조립을 그대로 쓰고, GoF 이름은 이 문서에서만 쓴다.

### 1. 어휘 대응표

코드와 다른 문서는 왼쪽 어휘를 쓴다. GoF 이름을 클래스명·파일명·문서 본문에 넣지 않는다.
이 표는 외부 자료와 대조할 때 참고하는 용도이며, **GoF 이름이 등장하는 유일한 곳**이다.

| 저장소 어휘 | 대응하는 패턴 | 실제 위치 |
| --- | --- | --- |
| 저장소 포트 `EventRepository` | Repository | `webapps/fastapi/app/events/ports.py` |
| 어댑터 `InMemoryEventRepository` | Adapter | `webapps/fastapi/app/events/adapters/` |
| 조립 지점 | Composition Root | `webapps/fastapi/app/shared/dependencies.py` |
| 서비스 `EventService` | Facade (기능 내부) | `webapps/fastapi/app/events/service.py` |
| 테스트 대역 `FakeEventRepository` | Test Double / Fake | `webapps/fastapi/tests/conftest.py` |

Repository와 Composition Root는 **이 결정으로 새로 도입하는 것이 아니라 이미 있는 것**이다.
이 표는 그 사실을 기록할 뿐이며, 새로 만들 코드를 지시하지 않는다.

### 2. 패턴별 판정 질문

ADR-0002가 포트에 대해 정한 기준("프로세스 밖으로 나가는 I/O인가")과 같은 형식이다.
**나열된 조건에 전부 예라고 답할 수 있을 때만 만든다.** 하나라도 아니면 만들지 않는다.

| 패턴 | 만들어도 되는 조건 (전부 예여야 함) | 현재 상태 |
| --- | --- | --- |
| 포트 | 프로세스 밖으로 나가는 I/O인가 (ADR-0002) | 4곳 예약, `EventRepository` 1곳 구현 |
| Repository | 포트 기준과 같다. 별도 기준을 두지 않는다 | `EventRepository` 하나 |
| Facade | 두 개 이상의 **기능 디렉터리**를 가로지르는가 + 화면과 API가 그 조합을 함께 쓰는가 | 만들지 않는다. 기능이 `events` 하나뿐 |
| Strategy | 변형이 2개 이상 **실재**하는가 + 선택이 설정·런타임 값으로 이뤄지는가 + 각 변형이 독립된 의존성이나 상태를 갖는가 | 만들지 않는다. 후보는 신뢰도 등급 분류 하나이며 변형이 1개 |
| Observer | 한 도메인 이벤트에 **서로를 모르는 반응이 3개 이상** 붙는가 + 반응이 실패해도 원래 작업을 되돌리지 않아도 되는가 + 반응의 실행 순서가 결과에 영향을 주지 않는가 | 만들지 않는다. 반응 0개 |

"실재한다"는 것은 **지금 코드에 있다**는 뜻이다. 앞으로 생길 것 같다는 예상은 조건을
만족시키지 못한다. 그 예상이 맞는 경우보다 틀리는 경우가 많고, 틀렸을 때 남는 추상화는
지우는 사람이 없다.

### 3. Facade는 새로운 파일 종류를 만들지 않는다

한 기능 안에서는 **`service.py`가 이미 파사드다.** 라우터는 서비스 메서드 하나만 알면 되고
포트 조합과 순서는 서비스 안에 있다. 서비스 위에 파사드를 또 두면 ADR-0002가 대안 A
(완전 헥사고날)를 기각한 이유 — 엔드포인트 하나에 파일 6~8개 — 가 그대로 재현된다.

여러 기능을 조합하는 기능(예: `events`와 `cameras`를 함께 보여주는 대시보드)이 생기면
**그 기능의 `service.py`가 파사드가 된다.** `facade.py` 같은 파일을 만들지 않는다.
파사드는 파일 이름이 아니라 서비스가 맡는 역할의 한 형태다.

### 4. Strategy는 분기를 없애려고 만들지 않는다

`if` 세 줄을 클래스 세 개로 바꾸는 것은 읽기 쉬워지는 것이 아니다. 읽을 파일이 늘어나는 것이다.
Strategy가 값을 하는 지점은 분기가 있는 곳이 아니라, **변형마다 딸린 의존성과 상태가
다른 곳**이다.

승격 기준에 도달하기 전까지 판단 로직은 **순수 함수**로 둔다.
승격 후보인 자리는 코드 주석으로 표시해, 다음 사람이 기준을 다시 찾지 않게 한다.
현재 그 자리는 `webapps/fastapi/app/events/rules.py`다.

### 5. Observer는 도입을 보류한다

두 가지 이유다.

첫째, **가독성 목표와 정면으로 충돌한다.** Observer는 제어 흐름을 코드에서 지운다.
"이 함수를 실행하면 무슨 일이 일어나는가"를 호출 지점에서 읽을 수 없게 되고, 구독자를
전부 찾아야 답할 수 있다. AI가 생성한 코드를 사람이 이어받아야 하는 상황에서 가장
비싼 종류의 간접성이다.

둘째, **미결정 항목과 겹친다.** 서비스 간 통신 방식과 실시간 화면 갱신 방식이 정해지지
않았다. 인프로세스 이벤트 메커니즘을 먼저 만들면 나중에 메시지 큐가 들어올 때
이벤트 경로가 두 개가 된다.

트리거에 도달할 때까지는 **서비스 메서드 안에서 순서대로 명시적으로 호출한다.**
반응이 두 개까지는 그 편이 읽기 쉽다. 트리거에 도달하면 새 ADR을 쓴다.

### 6. 표에 없는 패턴은 코드에 넣지 않는다

Factory, Singleton, Decorator, Chain of Responsibility 등 여기 없는 패턴을 쓰려면
**이 표에 행을 추가하는 ADR을 먼저 쓴다.** 판정 질문 없이 추가된 패턴은
6개월 뒤에 왜 있는지 아무도 설명하지 못한다.

## Alternatives Considered

### 대안 A: 계획대로 Facade와 Strategy를 지금 도입한다

기능별 디렉터리마다 `facade.py`를 두고, 신뢰도 등급 분류를 Strategy 인터페이스와
구현 클래스들로 바꾼다.

- 장점: 구조가 먼저 갖춰져 있어 나중에 변형이 늘어날 때 자리를 찾기 쉽다.
  팀원이 패턴 이름으로 코드를 검색할 수 있다.
- 단점: 기능이 하나뿐인 지금 파사드는 서비스로의 얇은 위임 껍데기가 되고,
  Strategy는 구현체가 하나뿐인 인터페이스가 된다. 두 경우 모두 호출을 따라갈 때
  단계가 하나씩 늘 뿐 얻는 것이 없다. 잘못 예측한 자리에 만들어진 추상화는
  나중에 지우는 사람이 없어 그대로 남는다.
- 채택하지 않은 이유: ADR-0002가 완전 헥사고날을 기각한 논리와 같다.
  구조를 먼저 갖추고 필요가 따라오기를 기대하는 것은 순서가 뒤바뀐 선택이다.
  필요가 확인되는 시점을 판정 질문으로 정해두면 같은 이점을 비용 없이 얻는다.

### 대안 B: 패턴 규칙을 문서화하지 않고 코드 리뷰에서 판단한다

기준을 명시하지 않고, 과한 추상화가 보이면 리뷰에서 지적한다.

- 장점: 문서를 늘리지 않는다. 상황마다 유연하게 판단할 수 있다.
- 단점: AI 에이전트는 매번 다르게 생성하고, 리뷰어마다 기준이 갈린다.
  더 큰 문제는 시점이다. 리뷰 시점에는 이미 코드가 쓰여 있어 되돌리는 비용이 크고,
  "동작은 하니까"라는 이유로 통과하기 쉽다.
- 채택하지 않은 이유: 이 결정의 목적은 잘못된 코드를 걸러내는 것이 아니라
  **쓰기 전에 안 쓰기로 결정하게 만드는 것**이다. 리뷰는 그 시점을 지난 뒤다.

### 대안 C: GoF 이름을 1급 어휘로 채택한다

클래스명·파일명·문서 본문에서 Facade, Strategy 등의 이름을 직접 쓴다.

- 장점: 외부 학습 자료와 어휘가 일치해 검색과 대조가 쉽다.
- 단점: 저장소 전체가 포트·어댑터 어휘로 서술되어 있어 문서 다수를 함께 고쳐야 하고,
  고치는 동안 같은 것을 두 이름으로 부르는 구간이 생긴다. `EventRepository`를
  "저장소 포트"와 "Repository" 중 무엇으로 부를지가 매번 흔들린다.
- 채택하지 않은 이유: 어휘를 하나로 유지하는 것이 이 결정의 목적(읽고 이어받기 쉬운 코드)에
  더 직접적으로 기여한다. 외부 자료와의 대조는 위 대응표 하나로 충분하다.

## Consequences

**얻는 것**

- AI 에이전트에게 줄 수 있는 명확한 문장이 생긴다 — "판정 질문에 전부 예라고 답할 수
  없으면 만들지 않는다." 지시가 없을 때의 기본 동작이 "만들지 않는다"가 된다.
- 어휘가 하나로 유지된다. 새로 배울 개념이 늘지 않는다.
- "이건 패턴으로 빼야 하지 않나"라는 리뷰 논쟁이 표 조회로 끝난다.
- 도입을 미룬 이유가 기록으로 남아, 나중에 같은 논의를 반복하지 않는다.

**감수하는 것**

- 미리 만들지 않으므로, 트리거에 도달하면 그때 리팩터링이 필요하다.
  판정 질문은 그 시점을 알아차리게 할 뿐 작업을 없애주지는 않는다.
- 표를 갱신하지 않으면 문서가 코드보다 낡는다. 새 패턴을 쓸 때마다 이 파일을 열어야 한다.
- GoF 어휘로 검색하는 사람은 대응표를 한 번 거쳐야 한다.
- "실재하는 변형 2개"를 기다리는 동안 비슷한 코드가 두 벌 존재하는 기간이 생긴다.
  코딩 규칙의 "세 번째 나타나면 공통화를 검토한다"와 같은 태도다.

**영향받는 문서·코드**

- `docs/agents/fastapi-agent.md` — Rules와 Completion Checklist
- `docs/conventions/coding-convention.md` — 구조 절에서 이 ADR로 링크
- `webapps/fastapi/app/events/rules.py` — Strategy 승격 후보 자리
- `webapps/fastapi/app/events/ports.py`, `app/shared/dependencies.py` — 대응 어휘 주석
- `create-fastapi-feature`, `review-code` 스킬 — 판단 단계
