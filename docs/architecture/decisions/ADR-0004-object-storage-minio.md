# ADR-0004: 영상·스냅샷 저장소로 MinIO 채택

## Status

Accepted

## Context

영상과 스냅샷을 보관할 위치를 정해야 한다.
[아키텍처 개요](../overview.md)에서 MinIO를 후보로 두었고, 도입 여부 자체가 미결정이었다.

영상 데이터는 메타데이터와 성격이 완전히 다르다.

| 항목 | 메타데이터 | 영상·스냅샷 |
| --- | --- | --- |
| 크기 | 레코드당 수 KB | 파일당 수 MB~GB |
| 증가 속도 | 이벤트 수에 비례 | 녹화 시간에 비례 |
| 접근 빈도 | 조회마다 | 필요할 때만 |
| 개인정보 | 식별자 수준 | **얼굴이 그대로 담긴다** |

이 차이 때문에 두 데이터를 한 저장소에 넣으면 백업 주기, 보존 기간, 접근 권한을
분리할 수 없게 된다. [아키텍처 개요](../overview.md)의 "영상과 메타데이터의 저장 책임 분리"
원칙이 이를 요구한다.

## Decision

**영상과 스냅샷을 MinIO에 보관한다.**

- 바이너리 데이터는 MinIO 버킷에 두고, 메타데이터 저장소에는 **참조(버킷·객체 키)만** 기록한다.
  영상 바이트를 MongoDB에 넣지 않는다.
- backend는 [ADR-0002](./ADR-0002-backend-layered-with-ports.md)의 `ObjectStorage` 포트를 통해
  접근한다. MinIO SDK는 어댑터에만 둔다.
- 접속 정보는 환경변수로 주입한다. 자격 증명을 저장소에 두지 않는다.
- **S3 호환 API 범위 안에서 사용한다.** MinIO 고유 기능에 의존하지 않으면
  나중에 실제 S3나 다른 호환 저장소로 옮길 수 있다.

### 저장 정책은 아직 정해지지 않았다

MinIO를 쓰기로 한 것이지, **무엇을 얼마나 저장할지 정한 것이 아니다.**
다음이 확정되기 전까지 영상을 상시 저장하는 기능을 만들지 않는다.

| 항목 | 상태 |
| --- | --- |
| 상시 녹화 여부 (전체 저장 / 이벤트 구간만 / 스냅샷만) | **결정 필요** |
| 보존 기간과 자동 삭제 | **결정 필요** |
| 접근 권한 — 누가 영상을 열람할 수 있는가 | **결정 필요** |
| 개인정보 처리 근거와 고지 방법 | **결정 필요** |

영상에는 사무실 구성원의 얼굴이 담긴다. 저장 범위를 정하지 않은 채 기능을 먼저 만들면
지우기 어려운 데이터가 쌓인다. 이 항목들은 기술 결정이 아니라 합의 사항이다.

## Alternatives Considered

### 대안 A: 서버 로컬 파일 시스템

- 장점: 추가 구성 요소가 없다. 구현이 가장 단순하다.
- 단점: 서비스 인스턴스가 늘어나면 파일 위치가 갈린다. 접근 권한을 파일 시스템 권한으로
  관리해야 한다. 보존 기간 자동화를 직접 구현해야 한다.
- 채택하지 않은 이유: 초기에는 편하지만 배포 방식이 정해지는 시점에 반드시 걸린다.
  옮기는 비용이 처음부터 객체 저장소를 쓰는 비용보다 크다.

### 대안 B: 퍼블릭 클라우드 객체 저장소 (AWS S3 등)

- 장점: 운영 부담이 없다. 내구성과 수명 주기 관리 기능이 갖춰져 있다.
- 단점: 사무실 영상을 외부로 내보내는 것에 대한 합의가 없다. 비용이 사용량에 비례한다.
  배포 환경이 사내인지 클라우드인지 **결정 필요** 상태다.
- 채택하지 않은 이유: 개인정보가 담긴 영상의 외부 반출은 별도 합의가 필요하다.
  MinIO를 S3 호환 범위에서 쓰면 나중에 이 선택으로 옮길 수 있다.

### 대안 C: MongoDB GridFS

- 장점: 저장소를 하나로 유지할 수 있다.
- 단점: 영상과 메타데이터의 백업·보존·권한을 분리할 수 없다. 대용량 바이너리 처리가
  객체 저장소보다 불리하다.
- 채택하지 않은 이유: 저장 책임 분리 원칙에 정면으로 어긋난다.

## Consequences

**얻는 것**

- 영상과 메타데이터의 보존 기간·접근 권한·백업 주기를 따로 정할 수 있다.
- S3 호환이라 나중에 클라우드 저장소로 옮길 경로가 열려 있다.
- 개인정보가 담긴 데이터가 한 곳에 모여 접근 통제 지점이 명확해진다.

**감수하는 것**

- 운영할 구성 요소가 하나 늘어난다. 배포·백업·모니터링 대상이 된다.
- 메타데이터와 객체가 어긋날 수 있다. 참조는 있는데 객체가 없는 상태를 다뤄야 한다.
- MinIO 고유 기능을 쓰지 않기로 했으므로 일부 편의 기능을 포기한다.
