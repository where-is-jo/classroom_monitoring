# Architecture Decision Records (ADR)

**목적**: 되돌리기 어려운 기술 결정을 그 배경과 함께 남긴다.
**대상 독자**: 나중에 "왜 이렇게 했지?"를 묻게 될 팀원과 AI 에이전트.

## ADR이란

하나의 결정을 하나의 파일에 기록한 문서다.
무엇을 골랐는지보다 **어떤 상황에서 무엇을 포기하고 골랐는지**가 핵심이다.

코드는 결정의 결과만 보여준다. 왜 다른 방법을 쓰지 않았는지는 남지 않는다.
그래서 몇 달 뒤에 같은 논의를 반복하거나, 이유가 있어서 피했던 방법을 다시 시도하게 된다.
ADR은 그 반복을 막기 위한 기록이다.

## 언제 쓰는가

다음 중 하나에 해당하면 작성한다.

- 되돌리는 비용이 큰 선택 — 저장소, 통신 방식, 프레임워크, 프로토콜
- 여러 서비스의 구조에 영향을 주는 결정
- [Architecture Rules](../../agents/AGENTS.md#architecture-rules)의 예외를 두는 결정
- 대안을 검토한 끝에 하나를 고른 경우
- [아키텍처 개요의 미결정 항목](../overview.md#미결정-항목)을 확정한 경우

다음은 작성하지 않는다.

- 라이브러리 버전 갱신
- 되돌리기 쉬운 구현 방식 선택
- 코딩 스타일 — [코딩 규칙](../../conventions/coding-convention.md)에 둔다

## 작성 방법

1. [`ADR-0001-template.md`](./ADR-0001-template.md)를 복사한다.
2. 다음 번호를 붙여 이름을 짓는다: `ADR-NNNN-<결정-요약>.md`
   - 번호는 4자리, 순차 증가. 비어 있는 번호를 재사용하지 않는다.
   - 예: `ADR-0002-metadata-store-mongodb.md`
3. 모든 절을 채운다. `Alternatives Considered`를 비우지 않는다.
   대안을 적을 수 없다면 아직 결정할 만큼 검토되지 않은 것이다.
4. 결정에 영향받는 문서(아키텍처 개요의 미결정 항목 표, 서비스 README,
   루트 README)를 함께 갱신한다.

## 상태 관리

| Status | 의미 |
| --- | --- |
| `Proposed` | 제안됨. 아직 따르지 않는다 |
| `Accepted` | 확정됨. 이 결정을 따른다 |
| `Superseded by ADR-NNNN` | 다른 결정으로 대체됨 |
| `Deprecated` | 더 이상 유효하지 않음 |

**확정된 ADR의 내용은 사후에 고치지 않는다.**
결정이 바뀌면 새 ADR을 쓰고, 이전 ADR의 Status만 `Superseded by ADR-NNNN`으로 바꾼다.
과거 기록을 고치면 "그때 무엇을 알고 있었는가"가 사라진다.
