# RPAs / examples

새 RPA 프로젝트가 따라야 할 **예시 구조**를 문서로 정리한 공간이다.

여기에는 실제로 동작하는 자동화 코드를 두지 않는다.
복사해서 바로 실행되는 샘플을 만들면 유지되지 않은 코드가 남기 때문이다.
대신 아래 구조와 문서 항목을 참고해 새 프로젝트를 직접 만든다.

## 권장 디렉터리 구조

```text
RPAs/<rpa-name>/
├─ README.md            # 목적, 트리거, 입력·출력, 실행 방법, 실패 대응
├─ .env.example         # 필요한 환경변수 이름과 설명 (실제 값 금지)
├─ src/                 # 자동화 실행 코드
├─ config/              # 실행 파라미터 (비밀값 제외)
└─ logs/                # 실행 로그 (저장소 커밋 대상에서 제외)
```

`src`, `config`의 내부 구조는 자동화 규모에 맞춰 정한다.
작은 자동화에 불필요한 계층을 만들지 않는다.

## 프로젝트 README에 들어갈 항목

새 RPA의 `README.md`는 최소한 다음을 포함한다.

1. **목적** — 어떤 업무를 대신하는가
2. **트리거** — 수동 / 일정 / 이벤트, 실행 주기
3. **입력** — 대상 시스템, 조회 조건, 입력 파일
4. **출력** — 생성물, 전송 대상, 갱신되는 레코드
5. **성공 조건 / 실패 조건**
6. **필요한 권한과 계정** — 계정 종류만 적고 값은 적지 않는다
7. **환경변수 목록** — 이름과 용도
8. **실행 방법** — 실제로 검증한 명령만 적는다
9. **재시도 정책** — 자동 재시도 대상과 금지 대상
10. **중복 실행 방지** — 이미 처리한 대상을 식별하는 기준
11. **사람 확인이 필요한 단계** — 자동 진행하지 않고 멈춰야 하는 지점
12. **로그 위치와 형식**
13. **문제 해결** — 알려진 실패 사례와 대응

## 작성 순서

1. [RPA 공통 규칙](../README.md)을 읽는다.
2. `create-rpa-workflow` 스킬를 따라 업무를 정의한다.
3. `RPAs/<rpa-name>/`을 만들고 README를 먼저 작성한다.
4. 입력·출력과 실패 조건이 확정된 뒤에 코드를 작성한다.
