# state worker

탐지 결과를 직원 상태(근무중·통화중·부재중·외근)로 판정하는 워커다.

> 현재 상태: 구현 전. **이 워커를 둘지 자체가 `결정 필요`다.** 아래 [소유 서비스](#소유-서비스가-정해지지-않았다)를 먼저 읽는다.

## 소유 서비스가 정해지지 않았다

[아키텍처의 호출 방향 규칙](../../docs/architecture/README.md#상태-판정은-누가-하는가)은
탐지 결과의 해석을 `fastapi`의 책임으로 둔다. 반면 영상 파이프라인 설계는 판정을
파이프라인 안에 그린다. **어느 쪽으로 할지 확정되지 않았다.**

확정 전까지 다음을 지킨다.

- 판단 기준(미탐지 지속 시간, 신뢰도 임계값)을 코드에 박지 않고 설정으로 둔다.
- `inference` worker에 업무 상태 어휘(`근무중`, `부재중`)를 넣지 않는다.
- 이 디렉터리에 코드를 만들기 전에 소유 서비스를 먼저 확정하고
  [결정 기록](../../docs/architecture/decisions.md)에 남긴다.

`fastapi`가 소유하는 것으로 확정되면 **이 디렉터리는 지운다.** 빈 채로 남겨두면
어디에 상태 로직을 넣어야 하는지가 계속 모호해진다.

## 서비스 목적

"사람 1명, 신뢰도 0.87"과 "수화기 들림"이라는 관측을 "이 직원은 지금 통화중"이라는
업무 의미로 바꾼다. 관측 하나가 아니라 시간에 걸친 관측의 연속으로 판단한다.

## 책임

- 카메라·좌석과 직원의 대응 관계 해석
- 시간 기반 상태 전이 판정 (예: 미탐지가 일정 시간 이어지면 부재중)
- 상태 변경 이벤트 생성

## 포함하지 않아야 할 기능

- 모델 추론 → [`inference`](../inference/README.md) 책임
- 상태의 영속 저장과 조회 API → `fastapi` 책임
- 알림 발송 → `fastapi` 책임
